# 排障笔记

> Mac 环境排障经验汇总，用于答辩「分享排障经验」环节与团队沉淀。

## 1. mmdc 绘制架构图时 Chrome headless-shell 启动失败（macOS Monterey）

**现象**

用 Mermaid CLI（`@mermaid-js/mermaid-cli` 12.2.0）导出架构图时，报错：

```
Error: Failed to launch the browser process: Code: null
dyld: Symbol not found: (_objc_claimAutoreleasedReturnValue)
  Referenced from: '.../chrome-headless-shell/mac_arm-157.0.8103.50/...'
  Expected in: '/usr/lib/libobjc.A.dylib'
```

**原因**

mmdc 自动下载的 Chrome headless-shell（157 版）要求 macOS 13+（Ventura），而本机是 **macOS Monterey 12.7.6**，`libobjc` 缺少新版符号，二进制无法启动。

**解决**

改用系统已装的 Chrome 150 作为渲染引擎，新建 puppeteer 配置文件：

```json
// docs/diagrams/puppeteer-config.json
{
  "executablePath": "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome",
  "args": ["--no-sandbox", "--disable-gpu"]
}
```

导出时通过 `-p` 指定：

```bash
mmdc -p puppeteer-config.json -i arch.mmd -o arch.svg   # SVG 矢量
mmdc -p puppeteer-config.json -i arch.mmd -o arch.png   # PNG
```

本机以后导出任何 Mermaid 图，复用此配置即可。

**安装命令备忘**

```bash
npm i -g @mermaid-js/mermaid-cli   # 首次会下载 Chromium，较慢
mmdc --version                     # 验证安装
```

## 4. Tier 3 复现踩坑点（Harbor 沙盒运行时）

> 环境：opencode 臂 + `qwen3.8-max`（token.cvte.com OpenAI 兼容网关），模型源 CLI。
> 命令：`docker compose run --rm skillevaluator tier3 /skills/positive/changelog --agents opencode --model openai/qwen3.8-max --timeout-multiplier 3 --tolerate-baseline-timeouts`
> 按出现顺序记录，均已在 `.env` 或容器内补丁解决。

### 4.1 agent setup 安装超时

**现象**：opencode 安装阶段 `npm i -g opencode-ai@1.19.5` 需联网，容器内直连 PyPI/npm 易超时或被墙，导致 tier1/tier3 的 `skillspector-llm` 阶段因 numpy 等依赖下载超时而失败。

**解决**：`.env` 设 `UV_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/`、`UV_HTTP_TIMEOUT=300`，走阿里云镜像 + 拉长超时。

### 4.2 数据集缺 git 仓库

**现象**：changelog 任务要求 git init + 提交 + 过滤 changelog，但原始数据集目录非 git 仓库，verifier 阶段失败。

**解决**：重写 `evals.json` 为自包含任务（`git init` + 5 次 commit + 按规则过滤 changelog），不依赖外部 git 历史。

### 4.3 judge 墙钟预算不足（LLM judge time budget exhausted）

**现象**：accuracy judge 报 `LLM judge time budget exhausted`。默认 `SKILL_EVAL_LLM_JUDGE_BUDGET_SEC=180`，qwen3.8-max 经 token.cvte.com 推理慢且会 429 重试（backoff 最大 30s），180s 在 baseline 臂 accuracy judge 处耗尽。

**关键点**：该值**独立于** `--timeout-multiplier`，后者不缩放 judge 预算，需单独调。

**解决**：`.env` 设 `SKILL_EVAL_LLM_JUDGE_BUDGET_SEC=600`。

### 4.4 opencode EPIPE（stdbuf -oL tee 管道崩坏）

**现象**：with-skill 臂 opencode 崩溃，写 stdout 经 `stdbuf -oL tee` 管道时报 broken pipe。

**解决**：补丁 `/usr/local/lib/python3.12/site-packages/harbor/agents/installed/opencode.py`，把 `2>&1 </dev/null | stdbuf -oL tee {path}` 改为 `</dev/null > {path} 2>&1`，去掉管道、消除 EPIPE。

### 4.5 opencode exit 1 提前退出（fire-and-forget bug）

**现象**：修完 EPIPE 后，opencode 仍以 exit code 1 退出，但 JSONL 已完整、却无 `result` / `error` 事件。根因是 opencode 1.19.5 已知 bug（anomalyco/opencode#29131 / #31365）：fire-and-forget 事件循环导致成功也提前退出。

**解决**：补丁 opencode.py 的 `run()`，用 try/except 包裹 `exec_as_agent`，捕获 `NonZeroAgentExitCodeError` 时若 `_error_messages()` 为空则视为成功（信任 JSONL `type=error` 事件，而非退出码）。

### 4.6 accuracy judge 读超时（socket read timed out）

**现象**：accuracy judge 报 `The read operation timed out`。`_call_openai_compatible` 硬编码 `timeout=90`（socket read），accuracy 判定 prompt 最长（5 个 criteria + question + ground_truth + agent_text），qwen3.8-max 推理超 90s。

**关键点**：该 timeout 受墙钟预算 `SKILL_EVAL_LLM_JUDGE_BUDGET_SEC` 钳制（min 取小），需同步调大。

**解决**：补丁 eval.py，新增 `_resolve_judge_request_timeout()` 读 `.env` 的 `SKILL_EVAL_LLM_JUDGE_REQUEST_TIMEOUT_SEC`（设 300），替换两处 `timeout=90`。

### 4.7 跨阶段环境约束

- **Docker Desktop VirtioFS 绑定挂载**：VirtioFS/gRPC-FUSE 不会把 `*at` 新建条目反映到已打开目录 fd 的 readdir，导致 SkillEvaluator 描述符式安全拷贝误判 staged 树为空，报 `staging tree has unexpected or missing entries`。解决：`.env` 设 `SKILLEVALUATOR_FORCE_PATH_COPY=1` 强制 path-based fallback。
- **LLM 网关 RPM 限制**：token.cvte.com 有 RPM 限制，高并发触发 429 导致语义分析 incomplete。解决：`.env` 设 `SKILLSPECTOR_MAX_LLM_CONCURRENCY=2` 串行化请求。
- **baseline 臂执行更慢**：无 skill 辅助，baseline agent 600s 内完不成，报 `AgentTimeoutError`。解决：`--timeout-multiplier 3`（setup 360s→1080s、exec 300s→900s）+ `--tolerate-baseline-timeouts` 兜底。

### 4.8 baseline 臂运行慢因（agent-loop 日志分析）

**现象**：baseline（without-skill）臂明显慢于 with-skill 臂，600s 内完不成，需 `--timeout-multiplier 3` 才跑完。

**分析**：opencode 臂每次运行都会把 agent loop 完整日志写入 `opencode.txt`（每步 `step_start`/`step_finish`/`reasoning`/`tool_use` 事件，含毫秒时间戳 + input/output/reasoning/cache token 计数）。逐步解析两次运行：

| 指标 | baseline（无 skill） | with-skill |
|---|---|---|
| step 数 | 24~25 | 18 |
| 总 wall-time | 353~480s | 173~262s |
| 总 reasoning tokens | 6851~13220 | 4389~6548 |
| 最慢单步 | 104~150s（reasoning 3371~4987 tok） | 57~115s |

**根因**：不是网络或 429，而是 qwen3.8-max 是 reasoning 模型，无 skill 指引时 agent 在关键决策点（git init、提交拆分、changelog 规则推导）触发超长推理——单步串行生成 3000~5000 个 reasoning token，wall-time 与 reasoning token 强正相关，单步可耗 100~150s。这类深推理步通常只有 2~4 步，却占总耗时 60~70%。with-skill 臂因 skill 给出明确步骤与规则，单步 reasoning token 上限约 1800，全程快约 2.8 倍。

**沉淀**：已在 harbor `opencode.py` 加 `_write_timing_log()`，每次运行后自动把逐步耗时/token/tool 汇总写入 `opencode-timing.log` 并用 logger.info 打印摘要，后续无需手动解析 `opencode.txt` 即可定位慢步。

### 5.1 公司 Skill 库 cskills CLI 拉取

**现象**：直接 curl / WebFetch 打公司 skill 库 `skills.gz.cvte.cn` 的 `/api/skills` 返回 401，无法拉取清单。

**原因**：接口需 `x-iac-token` 或登录 Cookie，匿名请求一律 401。

**解决**：改用公司 `cskills` CLI（v5.9.4，位于 `~/.local/bin/cskills`，PATH 已写入 `~/.zshrc`）。`cskills login` 飞书扫码 SSO 登录一次后凭证存本地，后续 `cskills find <关键词>` / `cskills info <name>` / `cskills add <name>` / `cskills group info <name>` 均可直接拉取（当前账号 `i_yangyuhan011148`）。
