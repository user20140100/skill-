# AppCode、页面配置与发布

## 1. AppCode 申请

需要申请 AppCode 时，直接提供 [AppCode 申请页](https://jdy.cvte.com/app/67a6e48abd6e4dc0143c371f/entry/67a6f4e6aa8f25fd98a4d044)，让用户按页面要求自行办理。无需先由 Skill 收集申请表字段，也不代为提交或默认转负责人办理；申请完成后使用实际获批的 appCode 继续接入。

- 新业务 URL 的 `system` 使用 appCode。
- 新业务配置键和 `systems[system].systemCode` 均使用 appCode。
- 不从历史系统表复制别名。

审批后 UC 测试和生产自动配置；统一登录只自动配置测试环境。

## 2. 页面定制

业务方在 [统一登录测试定制平台](https://id-admin.test.seewo.com/platform/service/system/edulyse-ops-buddy) 按 appCode 配置。当前可面向业务方说明的能力包括：

- 页面版本、手机号区号、排版和 Seewo 标识。
- 扫码、短信、注册、重置密码、其他登录、机构登录等入口开关。
- 登录过期时间。
- 主题色、hover/点击色、Tab/顶部颜色。
- PC 背景图、侧边图、PC/移动 Logo 和浏览器 Icon。

业务方不直接编辑 Apollo。所有业务方配置均热更新，发布后等待约 5 分钟再验收，无需重启。

### 港澳手机号接入

先主动提供 [港澳登录效果预览（测试环境）](https://id.test.seewo.com/login?system=bloom)，让业务方了解页面效果，无需先申请 appCode 才能预览。同时说明：页面上的 bloom 是示例业务的品牌展示，正式接入可通过定制平台改成自己业务的名称、Logo 和样式。提醒用户先在手机号输入处选择中国香港（+852）或中国澳门（+853），再输入对应手机号登录。

港澳手机号属于常规云端统一登录接入。业务方在定制平台为自己的 appCode 选择新版（V2）页面，确认区号选择器可用；登录时选择中国香港（+852）或中国澳门（+853）。其余申请、同域 Cookie/跨域 Ticket、iframe、回调白名单和生产迁移均沿用常规流程，不因港澳手机号单独转人工或改用其他认证体系。

- 标准 Web 使用 `/login?system=<自己的appCode>`，嵌入使用 `/login-iframe?system=<自己的appCode>`；按实际场景补齐回调和跨域参数。
- V2 是页面配置，不是 `/login/v2` 地址。预览链接的 `system=bloom` 仅用于体验，正式接入替换为自己的 appCode。
- 新接入不使用临时过渡入口 `/m/login?loginType=HK`；已有业务迁移仍需验证实际页面形态和回调。
- 发布配置约 5 分钟后，检查 +852/+853 可选择，并用对应测试账号验证登录与业务回调；生产同步迁移页面及区号配置。

对新手先给预览链接并简述：“可以先看看效果，页面上的 bloom 品牌可定制成你们自己的；先选择香港或澳门区号，再输入手机号登录。正式接入走常规流程，在定制平台选择新版页面即可。”再按业务域名和页面形态继续接入。

## 3. 协议更换

登录页面和扫码页面的协议支持更换：

1. 先确认修改测试还是生产环境。
2. 业务方飞书联系刘文祺，并提供环境和 appCode。
3. 刘文祺给业务人员开通权限并提供对应环境的配置域名。
4. 业务人员自行修改。
5. 等待约 5 分钟热更新后验收对应页面。

不得猜测配置域名、代称已授权或代替负责人执行权限操作。

## 4. 回调地址与域名白名单

区分“本次跳到哪里”和“该域名是否允许回调”：

- `redirect_url`：业务方可直接在登录 URL 中传入编码后的完整目标地址。标准 Web 登录优先采用传入且通过校验的地址；未传时才按对应入口的默认逻辑处理（如 `systems[appCode].url`）。默认回调配置不是要求每次把新页面地址写进 Apollo。
- `callbackIframeUrl`：iframe 登录成功后的中继回调地址，也可通过 URL 参数传入；与 `redirect_url` 职责不同。iframe 父页面收到登录结果、建立业务会话后，可自行决定停留、刷新或跳转，不能承诺 `redirect_url` 会自动让整个父页面跳转。
- `redirectUrl.domains`：Apollo 中允许回调的域名规则，不是逐条完整回调 URL 清单。传入的外部绝对地址仍需通过此校验；URL 参数优先不等于绕过白名单。

已有规则覆盖目标域名时，直接拼接正确编码的回调参数即可，无需重复申请；同一已允许域名下更换路径或业务参数，通常不需要新增域名规则。测试和生产分别核对，不能因 Apollo 中已有很多条配置就认定任意域名均可用。

只有目标域名未被当前环境规则覆盖时，才让业务方飞书联系刘文祺，提供环境、appCode、业务域名和完整回调地址；按需补充页面形态和复现信息。权限不足无法核对时写“覆盖情况待确认”，不要直接断言缺少白名单或将新增配置列为所有接入的必经步骤。

不在白名单内的外部地址在当前代码中被替换为 `/403`，不会因 URL 中显式传参而放行。不要建议关闭、绕过或放宽校验。

## 5. 微信小程序业务域名校验

当业务方需要在微信小程序后台把统一登录域名添加为业务域名，并请求提供根路径校验 txt 时，只指导验证材料准备和转交，不展开完整小程序登录、跳转或会话适配。

业务方必须飞书提供给刘文祺以下三项核心材料：

- 要校验的完整域名。
- 对应的配置环境。
- 从微信后台下载的原始 txt 文件，保留原文件名和原始内容。

域名必须同时与微信小程序后台填写的业务域名、最终对外校验 URL 的域名一致。生产 `id.seewo.com` 与测试 `id.test.seewo.com` 按业务实际目标核对，不可混用，也不默认两个环境都配置。小程序名称和 AppID 可作为辅助定位信息，但不能替代以上三项材料，也不作为额外前置门槛。

可直接转交：

```text
配置环境：<测试或生产>
微信后台填写的业务域名：<完整域名>
附件：<微信后台下载的原始校验 txt，保留原文件名和内容>
```

由刘文祺安排对应环境配置。配置后访问 `https://<目标域名>/<原始文件名>`，核对返回内容与原 txt 完全一致，再由业务方回到微信后台完成校验。平台侧可在网关对该准确 GET 路径直接返回 `200`、`Content-Type: text/plain` 和 txt 原文，不进入登录后端；这是平台实现背景，不要求普通业务方配置鲸云、上传应用文件或申请网关权限。

该事项属于微信业务域名验证，与统一登录回调白名单不同。验证成功只证明微信可访问域名校验材料，不等于完整小程序登录联调成功。

## 6. 生产迁移

1. 测试环境完成登录、回调、退出和异常场景验收。
2. 整理测试环境的系统配置、页面定制和白名单。
3. 联系刘文祺把统一登录测试配置人工迁移至生产；生产不会自动同步。
4. 等待约 5 分钟热更新。
5. 执行最小生产冒烟和回滚检查。

Skill 不自动修改或发布生产 Apollo，也不把迁移请求视为已经生效。
