# 接入后验证

代码生成或修改后必须执行本文件。验证强度取决于可用环境，但必须区分静态检查、项目验证、测试环境联调和生产验证。

## 1. 静态检查

- 新业务所有 `system` 都使用 appCode，未复制历史别名。
- 测试使用 `https://id.test.seewo.com`，生产使用 `https://id.seewo.com`。
- 同主域未设置 `withticket`；非同主域使用小写 `withticket=true`。
- `redirect_url`、`callbackIframeUrl` 正确编码，目标域名核对已有规则；仅未覆盖域名列新增配置项，覆盖情况未知单独标注。
- 前端没有读取、保存、覆盖或在 URL 中传播 `x-token`。
- 项目没有自行采集密码或直调托管页面内部登录、注册、重置接口。
- Ticket 仅传业务后端，兑换后清除；按 60 秒和一次性消费处理。
- iframe 校验 `event.origin`、消息结构并避免重复处理。
- 日志、埋点和错误页不包含 Token、Ticket、密码或完整敏感信息。
- 完整小程序登录、原生 App、账号互斥和 UC Token 鉴权未被越界实现；微信业务域名校验仅输出材料与核验步骤。

## 2. 项目验证

按调用方项目执行适用命令：

- 构建或类型检查。
- 登录拦截、回调处理、Ticket 交换封装和业务 Session 单测。
- 回调开放重定向防护、重复回调幂等、无效凭证路径测试。
- iframe 消息来源和非法消息单测。

只记录真实执行的命令、退出码和结果。

## 3. 测试环境联调

至少按当前场景验证：

| 用例 | 预期 |
| --- | --- |
| 同域 Web 正常登录 | `/login`，Cookie 由服务端使用，正确回跳 |
| 跨域 Web 正常登录 | 返回 Ticket，后端一次兑换并建立业务会话，URL 清理 |
| Ticket 过期、篡改、重复消费 | 不建立业务会话 |
| 同域/跨域 iframe | 回调正常；跨域 origin 校验和 Ticket 兑换有效 |
| 退出并回跳 | 业务自身会话清理，回到允许地址 |
| 动态回调与白名单 | 已允许域名下更换路径/参数无需重复配置；标准 Web 采用有效传入目标，iframe 按中继/父页逻辑处理；未允许域名被拒绝 |
| 移动 Web/PC 扫码 | 对应入口、成功、取消和过期行为正确 |
| 港澳手机号（适用时） | 新版页面可选 +852/+853；对应账号登录、换票/会话及回调正常，生产页面与区号配置同步 |
| 页面配置 | 发布后等待约 5 分钟，主题、入口或协议正确生效 |
| 个人信息副本 | 登录态、验证码、频控、邮件和 2 小时链接有效期符合契约 |

缺少 appCode、白名单、测试账号或环境访问条件时，标记“未执行”，并给出补测条件。

## 4. 生产验证

只有生产配置人工迁移完成后才执行最小冒烟：

- 正确 appCode 和生产业务域名。
- 登录、回调和业务会话。
- 退出。
- 必需的页面定制和协议。
- 异常回调不放行。

生产发布和配置修改由人工完成，不属于本 Skill 自动操作。
