# 接入 Preflight

代码接入任务必须先执行本文件。目标是先从项目得到事实，再用最少问题确定接入分支。

## 1. 先只读检查项目

- 构建工具、语言、框架和待改模块。
- 是否有 BFF/网关、未登录拦截器、鉴权中间件、Session 或 Cookie 会话。
- 测试与生产业务域名；分别判断是否属于 `*.test.seewo.com`、`*.seewo.com`。
- 现有登录、注册、找回密码、回调和退出流程。
- 是否已有 appCode、`system`、历史 system 别名和环境配置。
- 页面形态：Web 整页、iframe、移动 Web、PC 网页扫码；微信小程序仅需业务域名校验时按配置协作处理，完整小程序登录和原生 App 识别后转人工。
- 登录完成回固定首页还是原访问页；回调是否有多个域名。
- 是否存在自行采集密码、前端读取 Token、URL 传 Token、跨域依赖 Cookie、未校验 `postMessage` 来源等风险。
- 项目可执行的编译、单测、集成测试，以及联调仍缺少的环境条件。

能从代码和配置判断的信息不重复询问用户。

## 2. 渐进式澄清

必须确定：账号归属、页面/终端形态、测试与生产域名、回跳目标、appCode 状态。

用户描述模糊时首轮最多问两个问题：

1. 用户最终使用希沃账号，还是公司的员工域账号？
2. 登录发生在网页、移动网页、PC 网页扫码，还是嵌入页面？

随后只追问真正会改变方案的缺失项。不要让用户选择 Cookie 或 Ticket；让其给出域名，由 Skill 判断。

## 3. 阻塞与可继续边界

- 账号体系不明：不能生成最终方案，可先给条件式方向。
- 域名不明：不能最终选择 Cookie/Ticket，可继续给两分支模板。
- appCode 未申请：可以完成代码骨架和配置占位，不能联调或宣称可用。
- 回调域名先核对当前环境已有白名单：已覆盖无需新增；确认未覆盖才联系刘文祺配置。无法核对时标为待确认，可继续代码和静态测试，不宣称回调联调通过。
- 缺少测试环境：运行可执行的本地检查，明确标记联调未执行。
- 旧文档、项目代码与现行口径冲突：新接入按现行标准设计；存量迁移记录差异，不能静默替换。
- 完整小程序登录、原生 App、账号互斥、特殊身份源：停止生成标准实现，整理信息后联系刘文祺。若只是微信小程序业务域名校验，则按 `configuration-and-release.md` 收集三项核心材料，不生成登录实现。

## 4. Preflight 确认摘要

进入代码实现前必须输出：

```text
Preflight 确认摘要
- 登录账号体系：
- 调用方模块与技术栈：
- 终端和页面形态：
- 测试/生产业务域名：
- 凭证传递：Cookie / Ticket / 待确认
- appCode 与 system 状态：
- 回调和退出目标：
- 现有鉴权与会话基础设施：
- 已发现的历史兼容或安全风险：
- 当前可直接实现项：
- 可执行的本地/环境验证：
- 用户或刘文祺待完成项：
```

不确定项写“待确认”，禁止填入猜测值。
