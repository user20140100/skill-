# requirement_completion_skill 维护规范

## 1. 维护范围

本规范用于维护 `requirement_completion_skill` 的模块知识、匹配规则、输出契约、样例和验证集。

## 2. 目录职责

- `SKILL.md`：skill 入口说明、读取路径、执行顺序
- `core/common_requirement_framework.json`：通用需求补全维度
- `core/task_templates.json`：不同任务类型的输出字段裁剪
- `schemas/input_schema.json`：输入结构约束
- `schemas/output_schema.json`：输出结构约束
- `modules/module_registry.json`：模块总注册表
- `modules/plugins/*.json`：单模块插件知识
- `rules/matching_rules.json`：模块识别与主次模块判定规则
- `rules/multi_module_resolution_rules.json`：多模块联动、优先级、恢复逻辑规则
- `rules/naming_conventions.json`：命名与分类规则
- `runtime/runtime_workflow.json`：运行编排流程
- `examples/few_shot_examples.json`：标准样例
- `examples/validation_set.json`：验证集
- `prompts/system_prompt.txt`：系统提示词

## 3. 新增模块流程

### 3.1 新增插件

在 `modules/plugins/` 新增 `<module_code>.json`。

必填字段：

- `module_name`
- `module_code`
- `category`
- `definition`
- `aliases`
- `keywords`
- `related_modules`
- `intent_patterns`
- `key_dimensions`
- `default_rules`
- `must_confirm_rules`
- `common_missing_items`
- `inference_rules`
- `output_templates.rewrite_template`

### 3.2 注册模块

同步更新 `modules/module_registry.json`：

- 新增模块注册项
- 保证 `module_code` 唯一
- 保证 `related_modules` 引用的模块已存在

### 3.3 补样例和验证

至少补：

- `examples/few_shot_examples.json` 中 1 条新模块样例
- `examples/validation_set.json` 中 1 条验证 case

## 4. 修改现有模块流程

### 4.1 只改模块知识

如果只是功能定义、默认规则、边界条件变化，优先只改：

- `modules/plugins/<module_code>.json`

### 4.2 需要同步改注册表的情况

只有以下信息变化时才改 `modules/module_registry.json`：

- `module_name`
- `aliases`
- `keywords`
- `related_modules`
- `category`

### 4.3 需要同步改说明的情况

如果变更会影响使用方式、输入输出、读取路径或执行顺序，还要同步更新：

- `SKILL.md`
- `runtime/runtime_workflow.json`

## 5. 规则类修改流程

### 5.1 模块识别规则

改这些场景时更新 `rules/matching_rules.json`：

- 新模块识别
- 主模块判定
- related 模块扩展
- 多模块消歧
- 置信度规则

### 5.2 多模块联动规则

改这些场景时更新 `rules/multi_module_resolution_rules.json`：

- 优先级冲突
- 恢复逻辑冲突
- 模式互斥
- 依赖合并
- 风险合并

### 5.3 命名与分类规则

改这些场景时更新 `rules/naming_conventions.json`：

- 新模块命名规范
- 分类标准
- alias 维护规则

## 6. 契约类修改流程

### 6.1 输入变化

修改输入字段时同步更新：

- `schemas/input_schema.json`
- `SKILL.md`
- 必要时更新 `runtime/runtime_workflow.json`

### 6.2 输出变化

修改输出字段时同步更新：

- `core/task_templates.json`
- `schemas/output_schema.json`
- `SKILL.md`
- `examples/few_shot_examples.json`
- `examples/validation_set.json`

## 7. 推荐修改顺序

每次修改按下面顺序执行：

1. 先改插件或规则
2. 再改注册表
3. 再改 schema / task template
4. 再改 few-shot 和 validation
5. 最后改 `SKILL.md`

## 8. 最低校验清单

每次修改后至少确认：

- JSON 文件可正常解析
- `module_code` 唯一
- `related_modules` 全部可解析到已注册模块
- 插件包含完整必填字段
- `inference_rules` 不少于 2 条
- `output_templates.rewrite_template` 存在
- few-shot 和 validation 已覆盖新增或修改内容
- `SKILL.md` 中路径仍与当前目录结构一致

## 9. 建议的变更类型

### 小改

- 单个插件字段修正
- 单个模块 alias / keyword 调整
- 样例补充

### 中改

- 新增模块
- 修改匹配规则
- 调整多模块联动规则

### 大改

- 修改输入输出 schema
- 调整任务类型字段
- 调整目录结构
- 重构 runtime workflow

## 10. 禁止事项

- 不要新增未注册的插件文件
- 不要修改 `module_code` 后不更新注册表
- 不要改输出字段而不更新 schema 和样例
- 不要把默认推断写成显式需求
- 不要让 `related_modules` 指向不存在的模块
