# 服务稳定性检测

目标是输出可落实的服务稳定性治理待办，不以“全部正常”的空泛结论或只有指标截图的结果结束。默认只读检测，创建本地报告；创建技能本身不触发生产扫描。

## 执行流程

1. 读取 [取证与工具](references/evidence-and-tools.md)。从当前仓库、用户给定信息和鲸云只读发现确定服务、环境、集群、应用、数据库和依赖；不要把同名测试/海外部署当成目标。目标不唯一且影响结论时询问，其他独立代码扫描可继续。
2. 固定绝对时间窗口。用户未指定时使用最近 24 小时；结合最近发布、实例启动时间及业务高峰检查。基线比较按需要追加，明确实际覆盖和查询上限。
3. 按下表逐项加载规则。全面检测覆盖六项核心方向，并做补充项的适用性筛查；用户只指定部分规则时尊重范围。JVM 规则在非 JVM 服务标记不适用，按语言选择等价运行时指标。
4. 先运行态发现，再回溯配置和代码；也从源码发现尚未触发的风险。运行态异常、代码风险、缺少观测和不适用分别记录，不能互相替代。发现异常 STW 必须按 [STW 规则](references/stw.md) 追查直接原因、触发来源和业务影响链，不能只停在“发现暂停，建议排查”。待办按独立动作逐行拆分，具体对象、当前事实与要改/查的内容在同一行；仅合并同一对象的重复动作，不以“根因相同”为由打包多项工作。
5. 必须读取 [报告契约](references/report-contract.md) 与 [固定报告模板](assets/report-template.md)，复制模板填充，保持格式版本、章节顺序、表格列名与任务字段一致，不为不同服务另拟结构。默认写入目标仓库 `docs/stability/<服务>-<环境>-<YYYY-MM-DD-HHmm>.md`；无仓库则写任务工作目录。用户指定位置优先，不覆盖既有报告。按契约完成交付检查，最终提供可点击的文件链接、重点待办和覆盖限制。

## 规则路由

| 规则 | 内容 | 何时读取 |
|---|---|---|
| SQL | [慢 SQL](references/slow-sql.md) | 数据库相关服务；分析已发生和未来风险 |
| ALARM | [告警完整性](references/alarms.md) | 核心项；必须核查鲸云策略实际绑定与启用状态 |
| GC | [GC](references/gc.md) | JVM 服务的 FGC、高频 YGC 与内存趋势 |
| STW | [异常停顿与根因定位](references/stw.md) | JVM safepoint、运行期插桩及其他停顿；读取其中链接的排查经验 |
| API | [高频慢接口](references/slow-interfaces.md) | HTTP/RPC 等在线服务 |
| POOL | [线程池与连接池](references/pools.md) | 存在线程池、数据库/HTTP/RPC/Redis 等池化资源 |
| EXTRA | [补充治理](references/additional-risks.md) | 全面检测的容量、依赖、发布、异步和可观测性筛查 |

## 约束与结论

- 线上取证优先使用 ccloud-cli：先加载 `ccloud-cli` 及相应领域技能，核对当前 help/metadata，再按 [能力矩阵](references/evidence-and-tools.md#规则与-cli-能力矩阵) 选择只读命令。CLI 已支持的查询必须先实际查询，不能直接打开页面取代；接口报错不等于能力不支持，也不等于服务异常。命令/依赖不可用时记录缺口，保留可做的源码和其他只读检查。
- GC 信息必须通过 ccloud-cli 获取，具体流程见 GC 规则。权限不足、能力不支持或数据缺失时标记“GC 检测未完成”，不得改用浏览器/APM 页面完成该项或据此判定正常。
- 当前尚未发现告警策略查询命令，告警核查通过 computer-use 访问 https://ccloud.cvte.com/alarm-v2/strategy 及平台实际规则列表。后续 CLI 若新增相应只读能力，优先使用。不要假装 CLI 已能返回策略，或用源码里有告警配置代替线上核查。
- 只读检查不自动授权生产变更。检测任务不包含建索引、修改告警、开关、JVM 参数、重启或发布，也不发送通知/测试告警。不要为了完成检测主动执行 GC、动态 attach/retransform、heap dump 或其他可能造成停顿的诊断。
- 进入容器时遵循 ccloud-runtime-debug 的命令与授权要求；缺少高风险诊断证据时先产出待办，不把侵入式操作当默认步骤。
- 单个 FGC 不等于不稳定；单条慢 Trace 不等于高频慢接口；日志无命中不等于未发生；应用启动期间事件不能直接归因到持续运行期。
- 外部排查经验仅保存必要方法与脱敏摘要；不得将带访问能力的分享链接、签名下载地址、授权参数或其令牌写入技能、报告和证据文件。来源可保留不含访问标识的文字说明。
- 未知值保留未知。指标缺失、单位未知、采样、截断、分片失败、权限不足均影响结论，不得据此给出通过。不硬编码本仓库或历史审计中的数据库地址、应用 ID、阈值与问题结论。

## 扩展规则

新增规则写入 `references/` 并加入路由，给出规则 ID、适用范围、证据来源、判定方式、误判边界、治理方向和验收条件。规则可以引用服务自身 SLO/阈值；若使用启发式阈值，标记为初筛依据并记录依据，不能包装成统一生产标准。
