# ALARM：告警覆盖与有效性

规则 ID：ALARM-01 覆盖缺失；ALARM-02 策略失效；ALARM-03 通知与处置缺口。

先检查当前 CLI 是否已有告警策略只读查询能力；当前 help 尚未发现该能力，使用 computer-use 访问 https://ccloud.cvte.com/alarm-v2/strategy ，读取界面真实信息。区分合并/静默策略和真正的告警规则，必要时查看旧版 https://ccloud.cvte.com/alarm/alarm-strategy ，不能只因新版搜索无结果认定没有告警。后续若 CLI 支持则优先使用，不假造命令。首次使用遵循 computer-use 工具文档，登录/权限阻塞记录为未验证，不绕过验证、不收集凭据。仅查看，不创建、编辑、启停策略，不发送测试通知。

按目标应用、生产环境、集群和版本/实例标签核查实际命中策略。服务策略可能继承团队/全局策略；先验证生效范围再认定缺失。不能仅凭有同名策略判定覆盖，也不能只凭当前未触发认定有效。

## 覆盖矩阵

对适用项逐一记录“有效覆盖/覆盖不足/已确认缺失/未验证/不适用”，给出策略名/ID、绑定范围、启用状态、指标与单位、阈值/持续时间、无数据行为、通知路由与静默情况。

- 用户影响：可用性/探测失败、HTTP/RPC 错误率与流量基数、延迟/超时；有 SLO 时核对其报警覆盖。
- 运行态：Pod 不可用/重启/OOM、CPU/内存、磁盘/inode、GC/长暂停。
- 饱和：线程池拒绝/排队、连接池等待/耗尽、依赖超时、数据库连接与慢查询。
- 异步：消息积压与最老消息年龄、消费失败/死信、关键定时任务失败或未运行。
- 告警系统：指标缺失、策略禁用/过期静默、联系人/值班路由、升级路径和处置文档。

这些是适用性检查方向，不要求每个服务都建一套一模一样的策略。阈值结合 SLO、正常峰值、持续时长及恢复条件，避免只增加噪音。

验收：策略真实绑定且启用、条件/无数据语义明确、通知有责任人和处置入口。通知可达性的历史证据可以补证；需要演练时列待办并单独执行，不在扫描阶段发消息。报告附必要页面证据/截图，遮蔽联系人敏感信息；未能验证投递应标“通知可达性未验证”。
