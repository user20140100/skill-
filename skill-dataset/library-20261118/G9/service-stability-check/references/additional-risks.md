# EXTRA：补充稳定性治理方向

全面检测时做以下适用性筛查，命中后再深入；不适用有理由，取不到证据标未验证。各方向也需遵守报告契约，代码配置缺口与线上故障分开。

线上先走 [CLI 能力矩阵](evidence-and-tools.md#规则与-cli-能力矩阵)：实例/配置使用 `app detail/pods/comprehensive`，容量使用 `observe metrics-list` → `metrics`，依赖使用 `observe dependencies` 与 Trace，历史异常使用 `observe logs/logs-count`。配置读取先过滤凭证字段。仅当当前能力或实际数据不足时记录缺口并补证，不把源码默认值当线上配置，不为完成扫描调用配置修改或容器执行命令。

| 规则 | 检查内容与证据 | 典型待办与验收 |
|---|---|---|
| CAP-01 容量与实例健康 | CPU throttling、OOM/restart、RSS/堆外/线程栈与容器预算、磁盘/inode、FD/线程数、单副本倾斜；读取 pods/detail、指标和既有日志 | 为实际瓶颈设预算与扩缩容策略；峰值资源有可解释余量，重启原因闭环。CPU 平均不高不能排除限流 |
| DEP-01 依赖韧性 | dependencies 与 Trace 对照代码；连接/读/总超时、重试次数/退避/抖动、熔断隔离、缓存击穿、下游限额 | 超时预算随调用链分配、重试有界且幂等、失败不耗尽本服务；拒绝或降级语义可验证 |
| REL-01 发布与生命周期 | startup/readiness/liveness、优雅停机、流量摘除、滚动可用副本、任务停机、版本兼容和配置生效证据 | 发布/退出期间流量不进入未就绪实例，在途请求和消费任务有界退出；探针依赖选择避免下游故障引发重启风暴 |
| ASYNC-01 消息与任务 | 积压量/最老消息年龄、消费速率/失败/死信、任务执行时长与调度周期、重入、多副本并发、重复消费 | 重试退避/死信与幂等闭环、积压可恢复；关键任务有超时和未运行告警，不在扫描中重放业务消息 |
| DATA-01 数据访问韧性 | 长事务/锁等待、事务内远程调用、连接预算、数据库容量/复制延迟（有适用证据时） | 缩短持锁时间和无界事务，验证业务一致性；不通过生产压测或主动锁表证明风险 |
| OBS-01 可观测性 | 核心指标、低开销 GC/safepoint 观测、Trace 关联、日志错误结构、数据缺失告警；采样/高基数字段 | 能关联实例/版本/请求并重建影响窗口，避免敏感数据泄漏和日志量反压；缺观测独立列待办 |
| CFG-01 配置与生命周期依赖 | 关键配置默认/线上差异、证书有效期、定时凭证更新、依赖单点、容量/配额边界；只查目标服务实际依赖 | 设置责任人与到期/容量预警、明确故障恢复步骤；不读取或输出凭证内容 |

按用户已明确的业务关键性决定范围。灾备/多活/故障演练可作为后续治理，不在只读审计中自动切流或制造故障。
