# SQL：慢 SQL 与未来风险

规则 ID：SQL-01 已发生慢查询；SQL-02 潜在访问路径风险；SQL-03 批处理与计数；SQL-04 数据/时间语义错误。

## 取证

1. 先核对当前 CLI 是否提供历史慢 SQL 查询；当前 `observe/resource` help 尚未发现专用 action，使用用户的慢 SQL 看板，核对实例、域名、库、阈值、时区、窗口及排序。后续若 CLI 新增则优先使用。检查面板查询和分页上限，不把最新 100 条当成 24h 全量。
2. 可导出数据或在现有允许查询界面汇总时优先全量聚合；否则分段取样。记录重叠去重策略、唯一事件 ID 是否存在、事件时间与 SQL start_time 的差异、高密度边界、SQL 文本截断。无法补齐的范围明确为样本统计，不能宣称精确总次数。
3. 通过 ccloud-cli 精确定位资源，对相关表逐条执行 SHOW CREATE TABLE，保留完整字段、类型、索引真实列序；必要时 SHOW INDEX 了解估算基数。基数和 AUTO_INCREMENT 不是精确表行数。
4. 扫描 Mapper、注解 SQL、ORM 条件、动态 SQL、分页工具、批处理与调用链；包含参数边界、定时任务、真实批量大小和配置分支。优先核实高耗时/高频/高扫描查询，再扩展其他代码风险。
5. 对完整、只读的代表 SQL 使用普通 EXPLAIN。计划估算与历史 rows_examined 分开写；截断 SQL不能原样重放。默认不执行 EXPLAIN ANALYZE、大表 COUNT DISTINCT 或无界统计来证明风险。

## 判定清单

- 大 OFFSET、全量导出反复从第一页偏移；游标是否与完整稳定排序键一致。
- 函数/隐式类型转换、前导通配符、位运算、OR 分支缺索引、组合索引非最左前缀，导致过滤不能用于有效定位。
- 索引虽命中但候选数很大；租户数据倾斜、逻辑删除历史膨胀、COUNT/DISTINCT/GROUP BY、回表与排序放大。低基数字段本身不意味着组合索引无效。
- 大 IN、N+1、重复拉取、无过滤条件的动态分支、分页/批量缺上限；拆批可能降低单次延迟但增加总成本。
- 多表关联扩行、派生表大 LIMIT、强制索引、宽行排序、锁等待/长事务。区分扫描成本与锁等待。
- 归档已有 ID 游标仍可能扫描海量不匹配行；时间字段类型和秒/毫秒、保留期解析、结束条件都要核对。

## 结论与治理

按样本次数、累计耗时、P95/P99（仅全量来源可得时）、最大耗时、扫描/返回比列热点；没有字段则不编造。共享库其他应用 SQL、部署与当前分支差异、运行时加密改写均需注明归属置信度。

治理项写清触发参数、代码位置、实际索引与计划、建议路径及语义约束。建议索引列序需结合等值/范围/排序和现有索引取舍，不输出“加个索引”式任务。不能把去除 DISTINCT、改 JOIN 为 EXISTS、OR 改 UNION ALL、改排序当成语义等价。

验收：结果及分页边界一致；在代表性大租户/批量下，实际扫描、累计耗时和延迟达到服务目标；控制写入成本与索引体积；窗口内相同指纹风险下降。检测阶段不建索引、不改 SQL。
