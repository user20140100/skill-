# 知识问答与问题排查的分段反馈

仅适用于 `personal-local-v1` 下实际执行了 `QA` 或 `TROUBLESHOOTING` 的任务。普通编码、提交推送、安装 Skill、MCP 配置、发布和反馈功能管理等操作不邀请评分；这些操作的对话也不纳入采集。不得因为会话中曾使用本 Skill，就给后续所有回答追加评分邀请。

## 会话与分段边界

开始符合范围的任务时，读取本规则，在当前宿主会话上下文维护以下状态（不写本地文件）：

- `conversationId`：优先使用宿主提供的可信会话 ID，格式为 `宿主名:会话ID`，最长 192 字符。宿主未提供 ID 时，首次生成 `宿主名:UUID`，在该会话后续任务始终复用；不得每次评分生成新的会话 ID，不使用 MCP requestId 代替。
- `lastSuccessfulFeedbackId`：上一条成功反馈的 ID，首次为空字符串。
- `lastSuccessfulEndMessageIndex`：上一条成功采集的结束序号，首次为 0。
- 当前任务是否已经邀请评分、是否已经评分，以及尚未确认成功的冻结载荷。

仅对本会话内符合采集范围的 user/assistant 可见问答消息按原顺序编号，从 1 开始。评分提示、评分回复、反馈成功通知、工具内容、平台上报预览及无关操作不计数；一个回答里附带的评分邀请应剥离，只将其业务答复作为一条消息。

每段从 `lastSuccessfulEndMessageIndex + 1` 开始，到本次被评价的最终答复结束。只取该区间新增问答，不能从会话最初问题重新复制，不能直接复用上一条反馈的 messages。

例：A 问答对应消息 1–4，A 评分提交成功；后续 B 问答对应消息 5–8。B 反馈只包含 5–8，并引用 A 的 feedbackId；两次评分和两段对话都保留。A 未评分且未拒绝上传时不推进成功边界，B 邀请需明确说明会包含此前尚未采集的问答。用户明确拒绝上传的内容不能因后续评分被重新纳入；若因此无法确定可连续采集的边界，停止采集并说明原因。

上下文压缩、重新加载 Skill、切换 QA/排障模式，都不能重置同一会话的 ID 或成功边界。优先从当前会话可见的上次成功工具回执恢复；无法恢复边界时不生成新会话 ID 冒充新会话，也不提交猜测区间。真实新建或分叉出的宿主会话使用新的 conversationId。

## 邀请评分

当本次知识问答或问题排查已经给出最终答复，且没有等待用户补充必需信息时，只邀请一次：

> 本次帮助你打几分？（1–5 分，5 分最满意，可附加意见）提交评分将上传上次成功采集之后、截至本次回答的新增问答，用于改进服务；首次评分从本会话首次使用知识问答或问题排查开始。也可以跳过。

同一个问题的追问、补充说明和继续调查不反复邀请；用户开始新的独立知识问题或排查问题，完成后可以再次邀请。用户继续业务问题时继续回答，不催促评分。普通感谢、跳过或沉默不上传。

评分针对最近一个尚未评价且已展示上传说明的问题；如果指向不清（如已转入 B，却回头评价 A），先澄清评分对象和采集范围，不把两个问题的评价混在一起。已成功采集的同一问题再次给分，不新建记录；告知其已评价，当前工具不支持修改旧评分。

## 何时提交

只有用户在已经看到上面说明后明确给出一个整数 1–5，并且没有表示拒绝上传，才调用个人 MCP 工具 `submit_skill_feedback`。普通业务文本中的数字、只说“谢谢”、跳过、沉默、拒绝上传或无法判断任务边界，都不调用工具。

调用前先核对本段第一条、最后一条、消息数量与上一成功边界。读取本段可获取的原始 user/assistant 文本，逐条保存，不用摘要、改写或上一段旧内容代替实际问答。确认本轮新增问题与最新答复均在段内。上下文只有摘要时，不将摘要伪装为原始消息。

调用参数：

- `consentNoticeVersion` 固定为 `skill-feedback/v2`。先核对工具 schema 支持本节分段字段；旧服务不支持时说明需要更新，不降级成 v1 全量采集。
- `conversationId` 复用上述会话标识；`taskType` 为本次实际模式 `QA` 或 `TROUBLESHOOTING`。
- `feedbackId` 为本次评价新生成的 UUID；`previousFeedbackId` 为上一条成功反馈 ID，首次明确传空字符串。
- `startMessageIndex` 和 `endMessageIndex` 是本段包含的起止序号，前者必须等于上一成功结束序号加 1。
- `skillName`、`skillVersion` 使用当前实际读取的入口名称与版本，不猜测。
- `score` 为 1–5 的整数，`comment` 为评分之外的可选意见。
- `messages` 只保留本段用户和 AI 展示的原始文本，按出现顺序使用 `role=user|assistant`；不要放入评分提示、评分回复、工具调用、工具结果、日志、源码原文、附件、Prompt、内部推理或其他任务。
- 原文完整且条数等于结束序号减开始序号加 1 时才用 `transcriptCompleteness=complete`。区间能可靠定位但部分原文缺失时用 `partial`，`incompleteReason` 明确缺失位置和原因，messages 只放能取得的原文。序号或边界不明时不提交；不能猜序号，也不能标成 complete。

## 成功推进与失败重试

提交前冻结本次 feedbackId、边界、分数和 messages。工具返回 `status=created` 或相同载荷的 `status=duplicate` 才算成功，告诉用户反馈已收集，并将成功边界推进到该段结束。迟到的旧段 duplicate 不得把边界回退。

网络或暂时不可用时最多重试一次，复用同一 feedbackId 和完全相同载荷；结果未知时保留冻结载荷及旧成功边界，不新建 ID 重发，不把后续新消息追加进重试载荷。仍未确认成功时说明未能确认收集，后续评价先解决这条待确认提交，不能绕开旧边界并行提交。

校验、权限、载荷过大或 `SEGMENT_CONFLICT` 不自动重试；边界冲突时依据实际成功回执恢复，不能改 conversationId、前驱或序号绕过检查。超限不截断后谎称完整。反馈失败不影响业务回答。

不要把对话或评分写入本地文件、排障报告、平台 session 或其他上报接口。`submit_troubleshooting_record` 仍按排障 Profile 原有的单独预览和确认规则执行，与本反馈工具互不替代。
