# 崩溃与死锁模式库

> 全谱系模式库，供 Agent 在反向推理链推到具体结构时对照识别。
> 每类含现象 / 根因 / 修复 / 通用规则。其中"C++ 对象生命周期"相关条目（构造期 UB / 循环引用 / 析构竞争）提炼自一份 C++ 崩溃复盘（飞书 wiki `ANYSwegrQiOHm6kJL4mc2v0anrc`），但模式本身适用于任何 C++ 项目。

## 一、崩溃模式

### 1.1 内存访问类

#### 空指针解引用

- **现象**：0xC0000005，faulting address = 0 或极小值
- **根因**：指针未初始化 / 已被置空仍使用 / weak_ptr 未 lock
- **修复**：使用前判空；回调中用 `weak_ptr::lock()` 检查对象存活
- **通用规则**：回调 / 跨线程访问对象前，先确认对象生命周期

#### UAF（use-after-free）

- **现象**：0xC0000005，faulting address 是已释放地址
- **根因**：对象析构后仍被回调访问（事件源比消费者晚停）
- **修复**：反向指针用 `weak_ptr`；析构先停事件源再释放消费者
- **通用规则**：见 1.4 析构竞争

#### 越界访问

- **现象**：0xC0000005，faulting address 是结构体成员小偏移
- **根因**：数组越界 / 错误 downcast / 缓冲区溢出
- **修复**：边界检查 / 用安全容器 / `dynamic_cast`

### 1.2 堆栈类

#### 堆破坏

- **现象**：0xC0000374，崩溃点通常**不是**破坏点
- **根因**：缓冲区越界写 / double free / 释放后写
- **修复**：用 PageHeap（`gflags /p /enable <proc> /full`）复现定位破坏点
- **通用规则**：堆破坏现场不可信，必须 PageHeap 复现

#### 栈溢出

- **现象**：0xC00000FD
- **根因**：无限递归 / 栈上大对象 / 线程栈过小
- **修复**：消除递归 / 大对象改堆分配 / 增大线程栈

### 1.3 异常控制流类

#### 未捕获异常 → terminate

- **现象**：`std::terminate` → `abort`，栈在 `_CxxThrowException` 后直接 terminate
- **根因**：工作线程 lambda 未包 `try/catch`（放大器）+ 某处抛异常
- **修复**：边界 `try/catch` 止血 + 修根因
- **通用规则**：**接住异常 ≠ 修好根因**；线程入口必须有边界 catch

#### 纯虚调用

- **现象**：`_purecall` 或 pure virtual function call
- **根因**：构造 / 析构期间调虚函数，此时 vtable 指向基类
- **修复**：构造 / 析构期间不调虚函数

#### CRT assert

- **现象**：CRT assertion dialog / abort
- **根因**：`_CrtCheckMemory` / 迭代器越界 / `_invalid_parameter`
- **修复**：看 assert 信息定位

### 1.4 并发时序类

#### 数据竞争

- **现象**：偶发崩溃，现场在不同运行间不同
- **根因**：共享数据无同步 / `atomic` 的 memory_order 配错
- **修复**：加锁 / 正确的 memory_order / 避免共享
- **通用规则**：偶发 + 现场多变 = 数据竞争嫌疑

#### 构造期 UB（成员初始化顺序）— 飞书坑一

- **现象**：偶发崩在构造期，栈在 `run()` 附近，但对象理应还没开始用
- **根因**：成员真实初始化顺序由**声明顺序**决定，与初始化列表书写顺序无关。线程排在 `io_context` 前 → 线程一启动就 `ioc_.run()`，但 `ioc_` 还没构造 → UB
- **修复**：调整声明顺序，依赖者（`thread_`）在被依赖者（`ioc_`）之后；初始化列表顺序与声明顺序一致
- **通用规则**：声明顺序 = 构造顺序；"一构造就开跑"的成员排在它访问的资源之后；`-Wreorder` 当 error

#### 析构竞争（释放顺序与依赖相反）— 飞书坑三

- **现象**：退出时崩溃，栈在回调访问 adaptor 成员
- **根因**：析构顺序 = 声明逆序 = 依赖逆序。外部事件源比消费者晚停 / `io_context` 比 adaptor 早死 → 析构期间回调打到已释放对象
- **修复**：三步走——①停外部事件源 ②排干 / Join 工作线程 ③释放消费者；给持有定时器 / 回调的对象幂等 `Stop()`
- **通用规则**：析构 = 依赖逆序；事件源必须先于消费者停；`Stop()` 用 `atomic_bool` 防重入

### 1.5 资源生命周期类

#### 循环引用泄漏 — 飞书坑二

- **现象**：对象反复创建 / 销毁后内存只涨不降，析构函数没被调用
- **根因**：父子互持 `shared_ptr`，引用计数谁也降不到 0
- **修复**：反向指针改 `weak_ptr` + `lock()` 检查
- **通用规则**：父子反向指针用 `weak_ptr`；`shared_ptr` 互指 = 成环嫌疑

#### 句柄泄漏

- **现象**：长时间运行后 `!handle` 句柄数持续增长，最终资源耗尽
- **根因**：HANDLE / socket / event 未 Close
- **修复**：RAII 包装（`std::unique_ptr` 自定义 deleter / `wil::unique_handle`）
- **通用规则**：系统资源一律 RAII

## 二、死锁 / 挂起模式

### 2.1 锁死锁

#### 互锁成环

- **现象**：`~*k` 多线程等待，`!locks` 显示锁 owner 互等
- **根因**：多个线程以不同顺序获取多把锁，形成等待环（T1 持 L1 等 L2，T2 持 L2 等 L1）
- **修复**：全局统一锁获取顺序；或用 `std::lock(m1, m2)` 原子获取多锁
- **通用规则**：锁获取顺序全局一致；持锁时不调外部接口（可能反向加锁）

#### 自锁（同线程重复加锁）

- **现象**：非递归锁被同线程二次获取，线程自死锁
- **根因**：持锁调用内部又加同一把锁的非递归 mutex
- **修复**：用 `std::recursive_mutex` 或重构避免重入
- **通用规则**：非递归锁禁止重入

### 2.2 资源耗尽

#### 线程池耗尽

- **现象**：任务排队不执行，`~*k` 线程池线程全阻塞
- **根因**：任务等任务（如线程池任务里同步等另一个任务）→ 池被占满死锁
- **修复**：任务里不阻塞等待池内任务；设合理上限 + 拒绝策略
- **通用规则**：线程池任务内禁止同步等待池内任务

#### 连接池 / 句柄耗尽

- **现象**：新请求无响应，`!handle` 句柄数高
- **根因**：连接 / 句柄泄漏或不足
- **修复**：泄漏排查（见 1.5 句柄泄漏）/ 调大池上限

#### OOM

- **现象**：`!heap -s` 堆占用极高，分配失败
- **根因**：内存泄漏（见 1.5 循环引用）/ 一次性大分配
- **修复**：定位泄漏类型

### 2.3 阻塞

#### 主线程消息泵停

- **现象**：UI / 服务无响应，主线程 `~*k` 显示在非消息处理处阻塞
- **根因**：主线程执行耗时操作 / 阻塞调用
- **修复**：耗时操作移到工作线程

#### 持锁等回调

- **现象**：线程持锁等回调，回调又需同把锁 → 自死锁
- **根因**：持锁期间调外部接口，外部回调反向加锁
- **修复**：持锁时不调外部接口；回调前释放锁

### 2.4 死循环 / 活锁

- **现象**：CPU 占满但无进展，`!runaway` 显示某线程 busy
- **根因**：循环条件错误 / 活锁（互相退让又重试）
- **修复**：修循环条件 / 加退避重试

## Code Review 检查清单（全谱系拦截点）

构造 / 生命周期：
- [ ] 初始化列表顺序与成员声明顺序是否一致？（`-Wreorder`）
- [ ] "一构造就开跑"的成员（thread / timer）是否排在它访问的资源之后？
- [ ] `shared_ptr` 是否成环？父子反向指针是否用了 `weak_ptr`？
- [ ] 持有定时器 / 回调的对象是否有幂等 `Stop()`？
- [ ] 析构是否按依赖逆序？事件源是否先于消费者停？
- [ ] 系统资源（HANDLE / socket）是否 RAII 包装？

并发 / 锁：
- [ ] 锁获取顺序是否全局一致？
- [ ] 持锁时是否调用了外部接口（可能反向加锁）？
- [ ] 非递归锁是否有重入风险？
- [ ] 线程池任务内是否同步等待池内任务？
- [ ] 共享数据是否有正确同步？`atomic` 的 memory_order 是否配对？

异常 / 边界：
- [ ] 工作线程 lambda 是否包 `try/catch`（边界 catch）？
- [ ] 跨边界（线程 / 模块）的异常是否被捕获处理？

## 与推理链衔接表

推理链推到具体结构时，对照本库：

| 推理结论 | 对照类别 | 验证方法 |
|----------|----------|----------|
| faulting addr = 0 | 1.1 空指针 | `.ecxr; k` 看指针来源 |
| faulting addr = 已释放 | 1.1 UAF / 1.4 析构竞争 | `!heap -p -a`；查析构顺序 |
| 堆破坏，崩溃点可疑 | 1.2 堆破坏 | PageHeap 复现 |
| terminate，无 catch 帧 | 1.3 未捕获异常 | `.exr -1` 看异常类型 |
| io_context 状态无效 | 1.4 构造期 UB / 析构竞争 | 查声明顺序 / 析构顺序 |
| 内存只涨不降 | 1.5 循环引用 | 查 shared_ptr 反向引用 |
| 多线程互等 | 2.1 锁死锁 | `~*k` + `!locks` 构等待图 |
| 线程池全阻塞 | 2.2 线程池耗尽 | `~*k` 看池线程状态 |
| CPU 占满无进展 | 2.4 死循环 | `!runaway` 找 busy 线程 |
