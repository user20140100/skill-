# SK05 平台基线

适用条件：确认 APK 的 `type=sk05`，并核对 APK/JS 版本与当前参考提交 `1735b1d25cfd20528e160011abb76689beaf5bcc`。`android/app/build.gradle` 将 `main + sk05 + uds + legacy` 装入 SK05；还要记录 `dev/demo/pro` 与 Debug/Release。历史包或热更新 JS 与基线不同时，先核实相关打点和分支。

## 装配与入口

| 能力与源码 | 当前分支 | 排查时的分流 |
| --- | --- | --- |
| `sk05/.../platform/binding/PlatformBindings.kt#createServices` | 系统栏用 Legacy/Signway；系统校时、APK 安装用 Legacy；电源、显示、状态灯、门禁输出、安装命令、平台版本用 UDS。 | 不要因机型是 SK05 就把所有硬件调用归到 Signway；先找实际调用的服务。 |
| `sk05/.../handler/DeviceHandler.java#init/getSerialCode` | `init` 立即释放初始化链；首次取 SN 才从 Signway 读取 `ro.boot.serialno` 并缓存。 | 初始化回调与 SN 读取是两个节点。 |
| `main/.../plugins/nfc/SK05IntentNfcPlugin.java` | 固件 `android.intent.action.cardid` 广播 → 卡号转换 → 响铃 → 通知 RN → 异步线程调用 Signway 韦根。 | 这条输入链不走 `NfcCardReadWorkflow`；`AndroidNfcPlugin` 是另一条输入路径。 |
| `uds/.../UdsPowerControl.kt`、`UdsDisplayControl.kt` | 通过 UDS 同步接口请求电源、显示能力。 | Adapter 返回和物理完成分开判定；计划决策还需追 `MCUOperationService`。 |

以上省略的前缀均为 `android/app/src/`。平台装配本身是代码事实，不能证明现场请求已进入对应 Adapter。

`ConfiguredPlatformServices.kt` 对未显式装配的能力返回 `UNSUPPORTED`；SK05 此基线未装配保活与人脸补光。系统栏的 Signway 调用与 APK 安装终态也应各自沿 Legacy Adapter 查，不能用 UDS 电源日志解释。

## 关联键与时序

| 链路 | 优先关联键 | 易误合并处 |
| --- | --- | --- |
| 启动与 SN | PID、同次启动、`[read] source=system_property/memory`、后续设备身份请求 | `source=memory` 是缓存再次读取；相邻的 `[init]` 与 `[read]` 不一定来自同一业务请求。 |
| 固件刷卡广播 | 同次广播的原始十进制卡号、转换后的 8 位十六进制、时间与 Activity 生命周期 | RN 使用十六进制，Signway 韦根使用十进制；要先按源码转换再关联，报告只用脱敏标识。 |
| 电源与显示 | 计划时间、`action`、请求时刻、进程与设备实际状态 | 同秒内多次计划/屏幕操作不能只按时间合并。 |

## 日志指纹与证据边界

| 搜索键 / 通道 | 能确认的节点 | 后续要找的节点或限制 |
| --- | --- | --- |
| `sn_sk05 [init] ... state=ready` / XLog | 初始化链放行。 | 不证明 SN 有效；找 `getSerialCode` 使用点和下游身份结果。 |
| `sn_sk05 [read] ... source=... result=...` / XLog Debug；`[error] ... stage=serial_code_read` / XLog | 按需读取结果或异常。 | `[read]` 是 Debug 级，缺席可能由级别/覆盖导致；报告脱敏 SN。 |
| `SK05IntentNfcPlugin cardId:0` / 直接 Android Log；`hexCardId:..., octCardId:...` / XLog | 前者是 0 值被丢弃；后者表示非零卡号已转换，接下来尝试 RN 通知。 | 直接 Log 未必在 XLog 文本里；活动页为空时可在转换后静默返回。卡号需脱敏。 |
| `SK05IntentNfcPlugin sendWiegand, cardId:..., type:...` / XLog | 线程到达 Signway 调用前。 | 日志在 `sendWiegand26/34` **之前**；既不能证明 SDK 调用成功，也不能证明门禁控制器收到。 |
| `UdsPowerControl [request]/[accepted]`、`UdsDisplayControl [request]/[accepted]/[not_ready]` / XLog | UDS Adapter 请求与同步接受/未就绪。 | `[accepted]` 不等于设备已关机、唤醒或屏幕状态已改变。 |

## 按现象定位断点

1. **启动后身份/绑定异常**：先对齐 `sn_sk05 [init]`、首次 `[read]`、设备身份消费者的时间和 PID。只有 `[init]` 时，写“已放行，SN 读取未在所给文本中证实”，不写“SN 读取失败”。
2. **刷卡有声音但页面或门禁无反馈**：先确定广播路径还是 `AndroidNfcPlugin`；广播路径按 `cardId` → `hexCardId` → RN 接收 → `sendWiegand` 查。响铃、RN 事件、韦根是分叉动作，某一项成功不能代替另一项。最小补证是同次刷卡的应用日志、RN 接收日志，以及门禁侧状态。
3. **定时电源/显示异常**：从 `MCUOperationService` 的计划决策追到 UDS Adapter；若只见 `[accepted]`，断点止于“请求被本地同步入口接受”，设备执行需 SDK/系统/现场证据。

| 最晚可见节点 | 当前能判定的范围 | 最小补证 |
| --- | --- | --- |
| `sn_sk05 [init]` | 初始化链已放行；SN 值未知。 | 同 PID 的首次身份请求与 `[read]`，或下游返回。 |
| `hexCardId`，无 RN 反馈 | 广播卡号已转换；RN 事件可能未被观察。 | Activity/RN 接收同次卡的文本与通道说明。 |
| `sendWiegand` | 线程运行到 SDK 调用前。 | SDK 异常、门禁控制器记录或现场动作。 |
| `UdsPowerControl [accepted]` | UDS 同步入口接受。 | 计划任务后续和设备电源/屏幕状态。 |
