# 分析契约

## 输入、版本与路由

输入为用户提供的**已解析可读** `.log`、`.txt` 等文本，加上现象、期望和大致时间。首版不假定已有 `.xlog` 解码工具或设备全量采集能力。参考源码提交为 `1735b1d25cfd20528e160011abb76689beaf5bcc`；`android/app/build.gradle` 采用 `yunban(dev/demo/pro) × type(sk05/sk06/sk22)`，同一提交的不同机型也有不同源码集。历史 APK、Debug/Release 和 JS 热更新版不明时，标注版本不确定性，不能直接把当前源码分支当现场事实。

1. 对每份文本盘点首末时间、时区、文件/行号、进程/PID、通道（XLog、直接 Android Log、RN Console 等）、重启与断档。先读 [日志来源与覆盖](logging-and-coverage.md)，确认“缺行”可能由通道、级别、节流、快照或时间窗造成。
2. 根据现象选 [SK05](platforms/sk05.md)、[SK06](platforms/sk06.md) 或 [SK22](platforms/sk22.md) 平台基线，再查对应的 domain；共享规则在 `references/shared/`。先找日志里的真实入口，再沿代码调用链扩展；不要因为一个关键词同时出现在多个 domain 就合并事件。
3. 对同一操作优先用实际传递的请求 ID、任务 ID、用户/卡/文件脱敏键关联，再用时间和 PID 辅助。多次同类操作或进程重启后 ID 复用时拆开分析；卡号、SN、人脸和手机号不在报告中明文呈现。

## 建链与证据等级

将链路写成 `入口 → 条件/调度 → 请求建立 → 本地接受/响应 → 状态提交 → 用户可见或外部结果`。每个箭头要有日志、代码或明确标注的推断；并行分支分别追，不把一个分支的成功当另一个分支成功。

| 证据类型 | 可写的结论 | 不能越过的边界 |
| --- | --- | --- |
| 日志事实 | 输入文本在 `文件:行号` 明确出现的事件、状态、时间与错误。 | 只能证明该打点所在层；相同文本可能因 Console/XLog 双写而重复。 |
| 代码事实 | 与已确认版本对应的源码分支、调用顺序、结果定义，注明路径与符号。 | 当前源码不能证明历史 APK 现场走过该分支。 |
| 推断 | 用日志事实、代码事实解释可能原因，并列出竞争解释与置信度。 | 不把“后续日志缺失”自动写成某模块失败。 |
| 待验证项 | 版本、时间覆盖、SDK/服务端/硬件状态等缺证节点。 | 指定最小补证，不用无法完成的全量采集作为默认前提。 |

状态词按**产生它的代码位置**解读。例如 `sk05/.../handler/DeviceHandler.java` 的 `[init] state=ready` 只表示释放初始化链；`sk06/.../handler/DeviceHandler.java` 的 `[capacity] state=release` 与 `[ready] result=valid` 也不是同一事实；`sk22/.../platform/udi/UdiRuntime.kt` 的 `[udi_init] result=requested` 只是请求初始化。`uds/.../UdsAccessControlAdapter.kt` 的 `[accepted] action=send_card` 是同步 Adapter 接受，`sk22/.../adapter/UdiDevicePowerAdapter.kt` 的 `[power_task_complete]` 是 UDI 回调，都不直接证明控制器动作或物理关机。以上路径省略了 `android/app/src/`。

“**已证实断点**”只用于有明确异常/拒绝日志或相互印证证据的最早失败节点。若只见成功的前段、后段未出现，则写“最早可见节点”和覆盖限制；有候选原因时写推断。HTTP 2xx、数据库写入、RN 派发、SDK 回调与用户/硬件结果分别占一个节点，不能互相替代。

## 报告格式

```markdown
## 结论
- 问题与当前判断：
- 置信度与原因：高 / 中 / 低
- 最早已证实断点（或最早可见节点）：

## 适用版本与日志覆盖
- APK/JS/机型/环境/构建类型；源码提交或版本不确定性：
- 文件、进程/PID、通道、起止时间、时区、缺口：

## 时间线
| 时间 | 文件:行号 | 脱敏日志事实 | 链路节点 | 判断 |

## 事实与解释
- 日志事实：
- 代码事实（提交、路径、符号）：
- 推断与替代假设：
- 待验证项：

## 下一步
- 最小补证（具体时间窗、进程、通道、TAG/关联键或外部状态）：
- 若已足够确认，修复方向与影响范围：
```

日志只能支持覆盖范围判断时也照此报告，不制造根因。只摘取可核对的最短原文片段，并保留 `文件:行号`；不贴完整 token、SN、卡号、姓名、人脸图片链接、请求头或大段响应。
