# 安全切面细则

## L0 红线（不可覆盖）

### SQL 安全
- 执行 SQL 前必须先 `SHOW CREATE TABLE` 确认字段和索引，不得凭记忆构造
- 诊断阶段禁止写操作（INSERT/UPDATE/DELETE/ALTER/DROP），除非用户显式授权

### MCP 调用
- 入参必须完整合法；依赖前序输出时，必须验证前序输出存在
- 禁止使用占位值、伪造值
- 引用 MCP 结果时必须引用具体调用返回，不得引用"之前查过的"模糊记忆

### 数据真实性
- 禁止在未实际执行查询时编造、模拟结果
- 查询结果需做基本合理性校验（非空、字段一致、类型匹配）
- 禁止把推测包装成结论；「事实」与「推测」必须分开标注

### 操作边界
- 高风险写操作、线上变更、责任判断 → 升级人工
- 诊断过程中禁止修改业务数据、配置或状态

## 与业务 skill 的协同

- 业务 skill 的排查思路、资源顺序、判断规则优先于壳的默认行为
- 业务 skill 要求执行的排查动作全部完成之前，壳不允许输出根因级结论
- 业务 skill 与 L0 冲突时，以 L0 为准
