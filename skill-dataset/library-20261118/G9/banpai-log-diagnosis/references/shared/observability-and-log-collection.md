# 日志采集与可观测性

本文件用于判断现有材料能够证明什么，以及提出最小补充采集动作。代码事实基于 ab680809；它不授权执行设备导出、IoT 指令或上传操作。

## 已实现的日志与导出能力

| 能力 | 当前实现 | 对诊断的含义 |
| --- | --- | --- |
| 应用日志 | LogUtil 委托 Mars XLog；启动时配置为全级别并开启控制台日志 | 领域手册中的 TAG 通常来自该通道，但归档是否完整仍取决于实际导出时机 |
| XLog 保留 | XLogInitializer 写入应用缓存目录的 xlog，最长 7 天、单文件最大 100 MB | 超过保留期或发生轮转后，缺少历史日志不能视为未执行 |
| U 盘导出 | DiskLogUtils.exportLogToUDisk 复制 data logs、启动与升级日志、MCU、Mosquitto、ANR、异常目录及刷盘后的 XLog | 优先索取同一次导出的完整目录，不只索取截图或单个过滤片段 |
| IoT 远程导出 | LogUploader 响应 uploadDeviceLog，生成压缩包后作为临时 CStore 文件上传 | 该 CStore 临时文件仅用于日志交付，不能外推到开门图片的保存策略 |
| HTTP 日志 | 默认接口为 BODY；CStore 与人脸特征为 BASIC | 对 CStore、人脸同步，应用层 TAG 通常比 HTTP body 更可靠；是否实际归档仍须核对 |

XLog 导出前会执行 flushXLog。当前仓库未提供对导出 XLog 文件的解码或转换流程；拿到非文本 XLog 文件时，应先确认可读方式，不要把它当作已完整可检索的纯文本。

## 先辨别导出物来源

文件名或目录名本身不能证明导出路径。特别是系统的 data log_boot 和 log_boot_last 快照，可能只包含系统滚动 logcat、内核日志、进程快照和 dropbox 条目；它们不等同于 DiskLogUtils 完整导出，也可能不携带应用 XLog。

因此：

- 在 log_boot 快照中未找到 XLog，只能说明该快照没有携带 XLog，不能推断应用没有写入。
- 若需要应用 XLog、ANR 或 MCU 等完整材料，应确认导出动作是否经 DiskLogUtils 完成，并索取其生成的上层导出目录。
- 先按应用 PID 和启动时间切分系统 logcat；设备启动早期可能出现未校时的日期，后续手工校时会使同一文件中的时间线不连续。

## 最小采集建议

| 问题类型 | 首选材料 | 需要的时间与关联信息 |
| --- | --- | --- |
| 单次用户操作失败 | 发生前后至少 30 秒的原始应用日志和 HTTP 片段 | 时区、设备、脱敏用户或卡号、taskId、orderId 或 ruleRecordKey |
| 重试、延迟同步或偶发问题 | 从首次入口到最终成功或失败后的完整时间窗 | 网络状态、重启、解绑、IoT 命令和任务残留情况 |
| 节目或外部 SDK 问题 | 应用日志加 Uips、下载或播放器可得日志 | 发布场地、有效期、节目变更时间、绑定状态 |
| 日志缺节点 | 一次完整 U 盘或远程导出物，并说明采集时间 | 导出方式、应用版本、是否跨日志轮转 |

可先按领域手册的 TAG 和固定文本筛选，但必须保留原始文件路径、时间范围和未匹配部分的说明。面对连续操作，窄时间窗加关联键比关键词全局搜索更可靠。

## 不能由缺失日志直接得出的结论

- HTTP 请求行缺失：可能是网络拦截、服务器地址未配置、Basic 日志覆盖有限、日志轮转或导出不完整。
- XLog 片段缺失：可能是未刷盘、保留期结束、导出范围不足或文件尚未解码。
- 没有 Uips 播放日志：当前应用源码不包含 Uips 内部下载、解码和渲染的完整可观测性。

报告中应将上述情况标为“当前材料未覆盖”，并明确下一步要补充的文件、时间窗或外部组件日志，而不是用“代码没有执行”替代证据。
