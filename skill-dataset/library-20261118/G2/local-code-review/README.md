# local-code-review

对本地 git diff 或 GitLab MR 执行规则驱动的代码评审，输出透明可追溯的结果。

## 适用场景

| 适用 | 不适用 |
|------|--------|
| 提供 branch/commit 对要求评审 | 单文件 ad-hoc 问题（直接回答即可） |
| 提供 GitLab MR URL 要求评审 | 无 diff 的架构设计讨论 |
| 需要明确规则驱动、有覆盖范围声明的评审 | |

## 快速开始

### 本地 diff 评审

```
帮我评审 main..feature/xxx 的变更，规则：禁止 console.log，所有公开函数必须有注释
```

### GitLab MR 评审

```bash
# 1. 设置 Token（需 read_api 权限）
export GITLAB_TOKEN=<your-token>

# 2. 对话中直接说：
帮我评审 https://gitlab.example.com/proj/-/merge_requests/42，规则：……
```

## 核心工作方式

1. **规则先行** — 没有规则时，AI 会先询问；或声明自选通用最佳实践规则，每个项目应该在自己的 CLAUDE.md 中说明评审规则
2. **机械规则用工具** — 凡是"禁止 xxx"类规则，必须用 `grep`/`rg` 扫描，不用肉眼
3. **诚实声明覆盖范围** — 跳过的文件、未检查的内容，必须在报告中明确列出

## 输出格式

- **默认**：Markdown 格式，直接输出到对话
- **HTML 报告**：仅在明确要求时生成（使用 `reference/report-template.html` 模板）

HTML 报告包含：概览 KPI、规则汇总表、问题详情（GitLab MR 模式下可点击跳转到对应行）、范围外发现、局限性声明。

## 关键约定

- **没检查的地方不能说"无问题"**，只能说"未检查"
- **范围外发现**不对用户隐瞒，放"额外发现"区块
- **规则中途变更**时，AI 会告知已检查文件的覆盖影响，由用户决定如何处理
- **文件超过 20 个**时，AI 会声明优先级策略并列出跳过的文件及原因
