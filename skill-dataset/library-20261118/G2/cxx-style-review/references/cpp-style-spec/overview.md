# 概述
## 1 说明

本文旨在通过制定统一的C语言、C++语言的编程规范，帮助开发者形成良好的、统一的编码风格，形成安全的编码意识，使得代码可读性更好、健壮性更高，从而在编码之初就能最大程度的避免可能产生的各种问题。通过该文的规则作为标准，我们可以统一且明确（没有歧义）的认定每行代码、每个字符（比如每一个空格）是否符合规范的要求。
本文中的各种规则，并非作者通过主观意愿制定的规则，而是参考了业界主流的规则定义，如《华为C语言编程规范5.0》（非公开文档）、《阿里巴巴Java开发手册1.4.0》（公开文档）、六环旧的《C/C++ 编码规范》等，或者是一些开源代码统一的良好的编码风格等等。参考这些规范，一是我们可以最大程度的学习到业界优秀企业的经验所得（他们在制定这些规则时肯定已经有了充分的考虑），二是可以让我们在学习第三方开源代码，或在业界技术交流时降低学习成本。
由于作者水平有限，本文可能存在诸多错误或遗漏的地方，欢迎各位读者指正、或参与到该文档的更新修订工作中，使得该文档更加完善。
最后再次阐明，本文严格的要求，并非是有意增加开发者学习成本、工作负担，而是为了让开发者能明确自己每一行代码、甚至每一个字符的意义，更好地写出高质量的代码。

## 2 核心原则

可读性(Readability)：代码虽然是给机器执行的，但在开发、维护过程需要人去阅读。清晰、一致的风格可以让开发者快速理解代码含义，减小维护与再开发成本。
简洁性 (Simplicity)：在保证算法效率、具备良好拓展性的前提下，尽可能用最简单、最直接的方式解决问题。避免过度设计和不必要的复杂性。
安全性 (Security)：始终优先考虑代码的健壮性和安全性，防止缓冲区溢出、内存泄漏、空指针、线程安全、死锁、隐式泄露等致命问题。
可维护性 (Maintainability)：代码应该易于维护和扩展，模块化、低耦合的设计是关键。
可移植性 (Portability)：代码应尽量避免依赖特定编译器、操作系统或硬件的特性，以保证在不同平台上的兼容性。

## 3 适用范围

a、本公司绝大部分的C、C++代码需遵循本文规则，因特殊情况而无法遵循本文规范（如工具产生的代码），可以通过附加说明与责任人审核的方式忽略对应规则。

b、引入独立成模块的第三方代码、linux内核代码等，可以保留源代码的编码风格，并在修改时也使用源代码的编码风格。（注意第三方代码定义，供应商提供的代码，已经属于公司需要维护的代码范畴，不属于第三方代码。）

## 4 规则考量分类

## 5 章节说明

本文主体部分分为三章，分别为：风格规约、实践规约、安全规约。每个章节描述的侧重点不同，其中风格规约主要描述命名、代码格式、注释等内容；实践规约主要描述语法点、关键字、库函数、工具在使用时的良好的方式；安全规约主要描述与安全编码相关的问题（包括程序健壮、信息安全等）。但也并非完全严格区分，比如实践规约中也可能含有排版相关的内容等（最显而易见的就是一条规则中可能会包含多条【考量类型】）。这些章节的重要程度也不分轻重，它们是相辅相成的，共同构成我们完整的编程规范。

每个章节中，有不同部分的分类，每个大类中又分小类，然后是每一条规则。其中每条规则包含【规则描述】，可能有【说明】、【正例】、【反例】内容，【规则描述】即规范准则的阐述，【说明】是对规则的补充或解释说明，【正例】是正确的做法，【反例】为错误的做法。
