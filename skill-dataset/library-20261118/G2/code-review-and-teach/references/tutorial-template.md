# 飞书教程模板（8 章节 Markdown 骨架）

> 本文件是 `code-review-and-teach` Skill 的参考文档，在执行流程 B 时按需加载。
>
> 用法：将 `{占位符}` 替换为实际内容，逐章节生成并给用户审阅。

---

## 教程结构总览

```
# {工具名称} 使用指南

## 📖 总览                           ← B.1：是什么 / 解决什么问题
## 🔄 替代方案对比                   ← B.2：其他方案 / 优劣势 / 选型建议
## 🔮 畅想与展望                     ← B.3：未来规划 / 扩展可能
## 📚 技术概念                       ← B.4：涉及的概念 / 类比解释
## 🚶 使用流程概览                   ← B.5：全局流程图 / 步骤概要
## 📋 详细步骤                       ← B.6：每步具体操作 / 截图
## ❓ 常见问题                       ← B.7：真实问题 / 解决方法
## ❓ 用户问题登记                   ← B.8：多维表格表单 + 清单链接
```

## B.1 📖 总览

### 写作目标
让读者在 10 秒内知道"这是什么"和"对我有什么用"。

### 模板

```markdown
# {工具名称} 使用指南

## 📖 总览

**{工具名称}** 是一个 {一句话描述}，帮你 {核心价值}。

### 没有它之前

{描述痛点，用第一人称，具体化}：
- 你需要手动 {操作 1}，每次耗时 {X} 分钟
- {操作 2} 容易出错，曾经 {具体例子}
- 新人需要 {X} 天才能上手

### 有了它之后

{描述改善后的体验}：
- 你只需要 {一句话指令}，{X} 秒搞定
- 零出错，自动校验数据格式
- 新人 5 分钟就能开始用

### 它支持哪些功能？

| 功能 | 说明 | 适用场景 |
|------|------|----------|
| {功能 1} | {一句话说明} | {什么时候用} |
| {功能 2} | {一句话说明} | {什么时候用} |
| ... | ... | ... |

### 效果展示

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| 操作时间 | {X} 分钟/次 | {Y} 秒/次 |
| 出错率 | {X}% | 0% |
| 新人上手时间 | {X} 天 | {Y} 分钟 |
```

### 写作检查清单
- [ ] 第一段话能让完全不了解的人看懂这是什么吗？
- [ ] "没有 vs 有"的对比是否具体？（不要只说"效率提升"，给数字）
- [ ] 功能列表是否完整？
- [ ] 是否有数据支撑？（耗时、出错率等）

## B.2 🔄 替代方案对比

### 写作目标
诚实对比，让读者理解"为什么选这个"，也清楚"什么情况不适合用这个"。

### 模板

```markdown
## 🔄 替代方案对比

### 方案总览

| 方案 | 原理 | 优点 | 缺点 | 最适合场景 |
|------|------|------|------|-----------|
| **{本工具}** | {一句话原理} | {优点 1、优点 2} | {缺点 1} | {推荐场景} |
| {方案 B} | {一句话原理} | {优点} | {缺点} | {场景} |
| {方案 C} | {一句话原理} | {优点} | {缺点} | {场景} |
| 手动操作 | 人工逐条处理 | 无需额外工具 | 慢、易出错 | 偶尔 1-2 条 |

### 详细对比

#### 方案 B：{名称}

- **原理**：{详细解释}
- **优点**：{具体优点，举例说明}
- **缺点**：{具体缺点，举例说明}
- **和本工具的差异**：{核心区别}

#### 方案 C：{名称}
...（同上格式）

### 选型建议

| 你的情况 | 推荐方案 |
|----------|---------|
| {场景描述 1} | {推荐方案} |
| {场景描述 2} | {推荐方案} |
| {场景描述 3} | {推荐方案} |

> 💡 如果不确定选哪个，可以先试试本工具，不行再换。
```

### 写作检查清单
- [ ] 是否列出了至少 2 个替代方案？
- [ ] 每个方案是否公平地写了优点和缺点？
- [ ] 是否给出了明确的选型建议（而非模糊的"看情况"）？
- [ ] 是否说明了什么情况下不推荐用本工具？

## B.3 🔮 畅想与展望

### 写作目标
让读者觉得这个工具会越来越好，激发使用兴趣和参与感。

### 模板

```markdown
## 🔮 畅想与展望

### 近期计划（1-3 个月）

- [ ] {功能 1} — {解决什么问题}
- [ ] {功能 2} — {解决什么问题}
- [ ] {功能 3} — {解决什么问题}

### 远期畅想

- [ ] {功能 A} — {大胆的想法}
- [ ] {功能 B} — {跨系统联动}
- [ ] {功能 C} — {自动化/智能化}

### 你的想法？

有好的想法或者需求？欢迎在文末的「❓ 用户问题登记」中提交。
我会评估可行性，优先级高的会排入近期计划。

> 📬 也可以直接飞书私信我：[@你的名字]
```

### 写作检查清单
- [ ] 近期计划是否具体可落地？（不要写不可能完成的事）
- [ ] 远期畅想是否有想象力？（不要只写已知需求）
- [ ] 是否有反馈入口？

## B.4 📚 技术概念

### 写作目标
用类比解释技术概念，标明"你需要关心吗"，降低新人的恐惧感。

### 模板

```markdown
## 📚 技术概念

使用本工具前，你只需要了解以下几个概念（都很简单，类比一下就懂了）。

### {概念 1}

| | |
|---|---|
| **是什么** | {一句话定义} |
| **类比** | {生活化的比喻}，比如："Token 就像你的银行卡密码，证明你是你" |
| **有什么用** | {在本工具中的用途} |
| **你需要关心吗** | 🟢 需要 / 🟡 了解即可 / 🔴 不需要 |

### {概念 2}

...（同上格式）

### 概念总结

| 概念 | 你需要做什么 |
|------|------------|
| Token | 从 IT 那里拿到，放到指定文件 |
| cskills | 记住 `cskills add xxx` 这个命令就行 |
| ... | ... |

> 💡 记不住没关系，Claude 会一步一步引导你，不需要背诵。
```

### 写作检查清单
- [ ] 每个概念是否用了生活化的类比？
- [ ] 是否标明了"你需要关心吗"？
- [ ] 是否给了新人"不需要背诵"的安全感？

## B.5 🚶 使用流程概览

### 写作目标
一张图让读者知道从哪开始、到哪结束、每步大概耗时。

### 模板

```markdown
## 🚶 使用流程概览

从零到成功使用，一共 {N} 步：

```
第 1 步              第 2 步              第 3 步              第 4 步
┌──────────┐      ┌──────────┐      ┌──────────┐      ┌──────────┐
│ {步骤名}  │ ──→  │ {步骤名}  │ ──→  │ {步骤名}  │ ──→  │ {步骤名}  │
│ ({耗时})  │      │ ({耗时})  │      │ ({耗时})  │      │ ({耗时})  │
└──────────┘      └──────────┘      └──────────┘      └──────────┘
{一句话说明}       {一句话说明}       {一句话说明}       {一句话说明}
```

### 各步骤概要

| 步骤 | 做什么 | 你需要准备 | 耗时 | 仅第一次？ |
|------|--------|-----------|------|-----------|
| 1. {步骤名} | {一句话} | {准备项} | {X 分钟} | 是 |
| 2. {步骤名} | {一句话} | {准备项} | {X 分钟} | 是 |
| 3. {步骤名} | {一句话} | {准备项} | {X 分钟} | 否 |
| 4. {步骤名} | {一句话} | {准备项} | {X 秒}  | 否 |

### 日常使用（仅需 N 秒）

配置完成后，日常使用只需：

```
{一条命令或一句话}
```

> 📋 详细操作见下一章 ↓
```

### 写作检查清单
- [ ] 流程图是否清晰（一图胜千言）？
- [ ] 每步是否标注了耗时？
- [ ] 是否区分了"仅第一次"和"日常操作"？
- [ ] 能否让读者扫一眼就知道大概要花多少时间？

## B.8 ❓ 用户问题登记

### 写作目标
在教程末尾建立问题反馈闭环，收集真实问题丰富 FAQ。

### 模板

```markdown
---

## ❓ 用户问题登记

遇到问题？**请先浏览已有问题清单**，看看是否已经有人问过并解决了：

👉 [查看问题清单]({飞书多维表格表格链接})  ← 优先看这里！

如果找不到答案，请提交新问题：

👉 [提交问题]({飞书多维表格表单链接})

### ⚠️ 提交问题时请注意

1. **必须附全屏截图**：不要只截错误弹窗，要截整个屏幕（包含操作界面、系统状态栏等）
2. **描述清楚你在做什么**：操作到哪一步了？
3. **描述期望的结果**：你本来想达成什么效果？
4. **描述实际发生的情况**：报了什么错？全屏截图上能看到什么？

> 💡 全屏截图能让我更快定位问题：看到你用的什么系统、哪个页面、上下文是什么。裁剪过的截图缺少关键信息！

> 📬 也可以飞书私信我：[@你的名字]
```

### 飞书多维表格字段设计

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 问题标题 | 文本 | 是 | 一句话描述，如"安装 cskills 报 permission denied" |
| 问题详情 | 多行文本 | 是 | 详细描述操作步骤、期望、实际结果 |
| 全屏截图 | 图片 | 是 | 必须提交全屏截图（不要裁剪），方便定位上下文 |
| 提问人 | 文本 | 否 | 默认匿名，方便后续追踪可填名字 |
| 提问时间 | 日期 | 自动 | 创建时间，无需用户填写 |
| 回复内容 | 多行文本 | 否 | 管理员（你）填写回复 |
| 回复时间 | 日期 | 自动 | 最后修改时间 |
| 状态 | 单选 | 自动 | 待回复（默认）/ 已回复 / 无需回复 |
| 关联文档 | 链接 | 否 | 管理员填写，指向相关教程 |

### 视图配置

- **表单视图**：用户看到的提交界面，隐藏"回复内容""回复时间""状态"字段
- **表格视图**：所有人可浏览的已回复问题清单，按"提问时间"倒序排列

### 创建步骤

```
1. lark-cli 创建多维表格
2. 配置字段（按上表）
3. 创建表单视图 → 隐藏管理字段 → 获取分享链接
4. 创建表格视图 → 所有人可查看 → 获取分享链接
5. 将两个链接填入模板
```
