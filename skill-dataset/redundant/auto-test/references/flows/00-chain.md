# 00. 五层链路子流程

## 目标

定义 auto-test 的最小可追溯链路：

```text
doc → plan → nl → spec → run
```

本阶段只定义链路规则，不生成具体测试资产。

## 链路规则

- `doc` 是上游需求依据。可以来自已有需求文档，也可以由代码反推，但不能缺失。
- `plan` 是测试决策层。它必须引用 doc；有代码时还应结合代码事实和页面事实。
- `nl` 是自然语言测试用例。它必须引用 plan；有代码时结合代码事实，无代码时只能表达 plan 中的测试意图。
- `spec` 必须引用 nl。
- `run` 必须引用 spec。

## 禁止事项

- 禁止跳过 doc 直接生成 plan。
- 禁止跳过 plan 直接生成 nl。
- 禁止在缺少代码时编造真实页面状态、按钮、selector 或实现细节。
- 禁止把“代码看起来像”当成需求真源；代码反推的需求必须标记为 `reverse-engineered` 和 `needReview`。

## 缺失处理

如果任何一层缺失：

1. 停止当前步骤。
2. 报告缺失的上游 artifact。
3. 说明继续生成会导致什么风险。
4. 给出下一步应执行的子流程。
