## 3-2 资源使用

### 3-2-1 指针

3-2-1-1、\[SC] 指针使用前，必须检查是否已经初始化，请不要使用野指针。

3-2-1-2、\[SC] 指针指向的内存、文件、链接、设备等资源的指针，在该资源释放后，该指针必须显式置空，防止使用悬空指针。
说明：指针显式置空后仍使用，编译器会做检查提醒，避免让错误进入到运行态。

正例：
```
char* buff = new char(BUFF_SIZE);
// do some thing...
delete buff;
buff == null; // 将指针显式置空，防止后续代码误用悬空指针
```

3-2-1-3、\[SC] 请不要将“泛”类型指针隐式转换为“专”类型指针，如C++中void\*类型隐式转为其他类型指针，基类类型指针隐式转换为派生类型指针。
【修正】

3-2-1-4、\[SC] 请不要定义函数的返回值为局部变量的指针或引用，容易出现使用悬空指针的错误行为，即使是局部的static类型变量，在传出函数外，被其他线程修改，也会造成不可预知的错误。

### 3-2-2 内存

3-2-2-1、\[SC] 内存申请/释放（malloc、`calloc` 、realloc/free，new/delete，new\[]/delete\[]）函数必须成对出现，最好在同一个函数中（并且注意是否存在异常、提前返回等可能导致释放资源函数执行不到的情况），或成对的内存申请、内存释放函数中（构造/析构、初始化函数/销毁函数等）；如果内存申请/释放函数未在同一函数中成对出现，必须在【申请内存的代码】处用注释说明对应【释放内存的代码】在哪、在【释放内存的代码】处用注释说明对应【申请内存的代码】在哪。

3-2-2-2、\[SC] 使用不安全的内存字节操作类函数，如memcpy()、memset()、strcpy()、sprintf()等,务必检查【目标地址内存大小的字节数】、【操作参数中指定字节数】，保证【目标地址内存大小的字节数】>=【操作参数中指定字节数】。
说明：项目中可以将这些函数封装为安全函数，避免发生内存访问越界行为。

【待平台封装安全接口】


3-2-2-3、\[SC] 存储过敏感信息、涉密数据的内存，如：密码、密钥、部件涉密数据、车辆VIN码、客户信息等，使用完成后必须清0后再释放。
说明：内存释放后，操作系统实际并不会清理内存中的数据，只是将内存区域标识为可用。那么这块内存在之后可能被其他进程使用，这时其他程序可以轻易获取这个没被清理的敏感数据；或者产生核心转储文件（core dump），被其他人窃取，会造成隐私泄露，对公司造成损失。

反例：
```
bool VerifyData() {
    char* vin = (char* )malloc(VIN_MAX_SIZE);
    if (vin == nullptr) {
       return false;
    }
    (void)memset(vin, 0, VIN_MAX_SIZE);
    // 从车云获取车辆VIN码
    Connect connect(IP, PORT);
    connect.getVinByKey(KEY, vin);
    // do some thing...
    free(vin); // 释放vin指向内存前，未先使用memset函数进行内存清0，存在风险
    vin = nullptr;
    return true;
}
```

【删除】

非特殊情况，动态分配的内存使用智能指针接收；

### 3-2-3 其他资源

3-2-3-1、\[SC] 文件、连接（套接字）、设备等资源句柄，在使用前必须进行初始化操作。

3-2-3-2、\[SC] 文件、连接（套接字）、设备等资源的使用应该与内存使用相似，即资源申请与释放函数应该成对出现（如构造函数/析构函数、初始化函数/销毁函数等），并尽可能在同一函数中调用（并且注意是否存在异常、提前返回等可能导致释放资源函数执行不到的情况），如果无法在同一函数中成对调用，必须在【申请资源的代码】处用注释说明对应【释放资源的代码】在哪、在【释放资源的代码】处用注释说明对应【申请资源的代码】在哪。

3-2-3-3、\[SC]\[DS] 需要多处位置使用、或反复使用的多个相同类型资源，请不要反复的申请与释放、请不要将占用资源、释放资源的操作散落到代码的各处，而是用“池化”的方式统一管理（如线程池、内存池、链接池等）。
