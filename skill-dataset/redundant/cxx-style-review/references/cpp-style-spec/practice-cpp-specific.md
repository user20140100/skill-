## 2-6 其他C++规则

### 2-6-1 命名空间/类/结构体

2-6-1-1、\[SC] 请不要在std命名空间下定义任何内容。
说明：std命名空间是属于C++的标准命名空间，不应该在此命名空间下添加任何代码，但可以特化std中的模板。

2-6-1-2、\[ES] C++代码中定义的枚举、变量、函数等都必须放在命名空间、类、结构体下，避免命名冲突的同时，也让对象所属范围、模块更清晰。
cvios::

2-6-1-3、\[ES] 类的构造函数，请不要有任何的业务逻辑，如果有业务类的初始化过程，请放到该类的init函数中。

【建议】

2-6-1-4、\[SC] 请不要在类的构造函数和析构函数中调用虚函数（如果遵循规则【2-6-1-3】大概率不会违背这个规则）。
说明：虚函数不能在所在类的构造函数中调用。 因为在对象的构造函数执行结束之前，对象的虚表指针还没有初始化好，调用虚函数不会有任何的效果。 如果你确实需要在对象的构造过程中调用虚函数，可以考虑使用工厂方法模式（Factory Method Pattern）。

【建议】

2-6-1-5、\[SC] 请不要在析构函数中抛异常。
说明：析构函数中抛出异常可能会导致程序直接崩溃退出，如果析构函数可能会抛出异常 ，请使用 try-catch 捕获并处理这些异常。

2-6-1-6、\[SC] 请不要用隐式类型转换构造对象，构造函数、类型转换操作符（单成员变量的类）都需要加explicit关键字修饰。
说明：隐式类型转换，由编译器自动完成，容易产生缺陷代码。

正例：
```
class Widget {  
public:  
    explicit Widget(const std::string& name); // Widget w("widget");  
  
    std::string ToString();  
  
    // 必须显式 std::string s = static_cast<std::string>(w);  
    explicit operator std::string ();
};
```

2-6-1-7、\[SC] 如果不需要使用默认的拷贝构造函数，请用delete关键字禁用；如果需要使用，请重写拷贝构造函数。

正例：
```
class Widget {
public:
    Widget() : size(1024), buffer(new char[size])
  
    // 使用delete关键字显式禁用
    Widget(const Widget& widget) = delete;
    Widget& operator=(const Widget& widget) = delete;
  
    ~Widget() {
        delete [] buffer;
    }

private:
    size_t size;
    char* buffer;
};
```



2-6-1-8、\[SC] 拷贝构造，拷贝赋值运算符，析构函数必须同时定义，即这三个函数有一个显式重写，其他两个也必须显式重写（或禁用）。

2-6-1-9、\[ES] C++的struct中请只定义成员变量、构造函数、析构函数、拷贝构造、赋值运算、简单的成员变量数据清除函数，不允许定义业务类函数。
说明：struct对成员的访问权限限制为默认，对成员封装能力有限，主要为对数据的描述，而不是数据处理。允许定义构造函数、析构函数、拷贝构造、赋值运算、简单的成员数据清除函数是为方便数据的初始化、数据清理（解决使用C语言字节操作函数无法处理非平凡类型变量的问题）。如有复杂业务，请定义为class，或将该结构体类型的变量作为函数的参数，交给其他函数处理。

【删除】

2-6-1-10、\[ES] 尽可能避免使用继承，优先考虑使用组合是否能满足业务需要。
说明:在软件设计原则中的”合成复用原则“中规定尽量用类对象的组合代替继承达到目的。原因是类关系：依赖、关联、组合、泛化（继承）中，类与类之间的耦合程度依次递增，我们应该优先考虑低耦合度的关系。

【建议】

2-6-1-11、\[ES] 请不要定义运算符重载函数。
说明：运算符重载函数，一个符号很难让开发者理解其功能、作用，容易产生歧义，应该用普通函数代替运算符重载，比如'\=='可以用名为Equals的函数代替。

【建议】

2-6-1-12、\[ES] 未被final修饰的类，其析构函数必须是public virtual或protected non virtual。其中当派生类对象在释放时需要表现出多态的特征（如需要基类指针指向派生类对象）、释放派生类对象时基类也存在需要释放的资源（需要调用到基类析构函数）时则声明为public virtual，否则声明为protected non virtual。
说明：如果基类指针指向派生类对象（或者派生类对象释放时需要调用到基类的析构），但基类未被声明为public virtual，则用基类指针指向派生类对象，执行delete时，非public无法调用，非virtual则只会调用到基类的析构，派生类的析构函数未被调用，因为析构函数不在虚函数表中；而用protected修饰则表示不希望外部用基类指针指向派生类对象时，可以被delete（delete只在基类、子类内部使用）。

2-6-1-13、\[ES] 重写基类的函数时，必须使用override、final修饰，其中不考虑后续被继承重写的，用final修饰，可能被重写的用override修饰。
说明：加上override、final关键字修饰函数，编译器会做重写函数检查，确保正确覆盖父类函数。

2-6-1-14、\[SC] 严格控制类成员的访问权限：
a.只有需要被外部访问的成员，才在public域声明；
b.只与子类共享的成员，用protected域声明；
c.只在本类中使用的成员，在private中声明；
d.类中的const成员变量，请用static修饰；只保留一份的成员变量使用static修饰，并且考虑是否要加const修饰；
b.virtual函数访问权限至少为protected的；
e.工具类构造函数在private域中声明，一般只提供const修饰的成员函数，如果有成员变量请用static修饰，请不要声明public、protected的普通的成员变量、函数。
说明：成员的访问权限越小，该类与其他类的耦合度就越低，修改的风险越小，维护成本越低。

2-6-1-15、\[ES] 访问类的静态成员时，请直接使用类名，而不是使用类的对象。
说明：使用类名访问成员，可以减少编译器的解析成本。

### 2-6-2 指针相关

2-5-2-1、\[SC] C++代码中，空指针统一使用nullptr表示，而不是使用NULL。
说明：C++中的NULL与C语言中的NULL含义是有区别的，在C++中NULL实际是int类型字面量0，在C语言中NULL实际是void\*(0)，做这个区别的原因是C++不允许隐式的将void\*转为其他类型指针，从而避免缺陷代码。虽然C++绝大部分场景中使用NULL的作用与nullptr一致，但为保持C++标准和代码一致性，统一使用nullptr表示空指针。

2-5-2-2、\[SC] C++代码中非特殊情况，如兼容原有代码、C语言接口等，优先使用智能指针（share_ptr、unique_ptr等），非必要情况下请不要使用裸指针。
【建议】

### 2-6-3 内存/线程/锁/文件等资源的使用与释放

2-6-3-1、\[SC] 使用控制多线程安全访问临界变量的互斥锁时，应该尽可能使用C++标准库提供的工具去管理，即lock_guard、unique_lock。
说明：使用C++标准库封装的锁工具去使用锁时，可以有效的避免死锁现象产生。

2-6-3-2、\[DS] 尽可能使用RAII方式管理资源（内存、锁、文件、设备等）的生命周期，即在类对象构造时申请持有，析构时处理释放。
说明：RAII方式管理资源的声明周期，运用了栈中的变量在函数帧出栈后被自动析构的特性，实现自动释放资源，有效防止资源被无效的占用。

【建议】

### 2-6-4 异常处理

【建议】

2-6-4-1、\[DS] 对于C++标准库中可以通过预检查避免的异常，就不要使用try-catch方式进行处理。

自己的业务类代码
【建议】

2-6-4-2、\[DS] 对于系统、模块频繁出现的多种类型异常，应该定义具体的异常类，而不是都用std::exception、std::runtime_error等通用异常，相应的catch中也应该写具体的异常类型，这样可以准确的获取异常信息与做相应的处理。自定义的异常类，请继承std::exception类或std::runtime_error类，命名为XxxException，用于和普通类区分。

2-6-4-3、\[DS] 请不要使用异常来做实现类似于条件控制的作用。

2-6-4-4、\[ES] try-catch中，try中的代码应尽可能少，稳定运行的代码请不要放在try代码块内。

2-6-4-5、\[SC] catch异常的类型应该大于等于throw异常的类型，以确保异常都能被捕获，捕获异常后应该做对应处理，而不应该什么事都不做。

### 2-6-5 其他

2-6-5-1、\[SC] C++代码中，设计类型转换时请不要使用C式的类型强转，而是使用C++标准库中提供的类型转换函数static_cast\<T>、const_cast\<T>。几个转换函数的作用、区别：
static_cast：用于基本类型之间转换、派生类对象（指针）转换为基类对象（指针）的上行转化，编译器会做安全检查；
const_cast：用于为变量添加或形式上去除const、volatile属性，不会改变变量的类型，注意形式上去除const属性的变量依然是不能修改的变量，只是在形式上让变量没有了const属性；
dynamic_cast：支持‌安全的下行转换‌（基类指针转派生类指针）和多态类型转换，依赖RTTI在运行时检查类型安全性，转换失败时返回空指针（指针）或抛出异常（引用）；
reinterpret_cast：执行‌低级别的位模式重新解释‌，如将指针转换为不同类型的指针或整数，不进行类型检查，因此‌风险高且不可移植。
其中：dynamic_cast、reinterpret_cast非必要情况下请不要使用，可能使程序产生未定义行为。

【建议】

2-6-5-2、\[ES] C++代码中，优先使用 using 关键字替代 typedef 关键字定义别名。原因是using支持模板参数，更强大。

【建议】

2-6-5-3、\[DS] 在使用 前置++（前置--）运算 与 后置++（后置--）运算作用一致的地方，请使用使用前置++（前置--）。
说明：对于基本类型变量，选择前置自增（自减）、后置自增（自减）影响不大，但对于调用（C++标准库、第三分库等）重载了自增、自减运算符的C++类、结构体时，后置自增（自减）运算符多了一次对象拷贝操作，增加了不必要的性能与内存开销。

【建议】

2-6-5-4、\[SC] C++代码中，非特殊情况，优先使用C++标准库提供的各种工具，如STL容器（std::string、std::vector等）、STL算法（std::sort()、std::for_each()等），这些容器可以自动管理内存、算法经过检验，可以放心使用。


2-6-5-5、\[DS] 使用C++中的STL容器时，优先使用性能更优的接口，如往容器中添加元素优先使用emplace相关的成员函数（vector的emplace_back()、map的emplace()等）。
说明：emplace相关函数的放入容器操作，可以使用到移动语义，减少对象拷贝。

【建议】
