# 客户段白名单与关键词表

`SKILL.md` Step 2 解析 BIOS 版本标识时的判据表。**这份文件就是解析器的配置**，直接改这里即可，不用动 SKILL.md。

---

## 一、客户白名单（命中 → 高置信，直接用）

格式：`分支段` 或 `分支段=显示名`（需要中文化时用等号右边）。**大小写敏感**。

| 分支段 | 显示名 | 出处（实测分支） |
|---|---|---|
| `诚迈` | 诚迈 | `CCB-H340-MA01/CRB_R02.03-Pre/Customer/诚迈/V0.04` |
| `Haier` | Haier | `CCB-H340-MA01/CRB_R02.02/Haier/Release/V0.03` |
| `Lecoo` | Lecoo | `MB.IWCL.ID02/CRB_05.72.17.0009/Release/Lecoo/V0.09` |
| `GX` | GX | `CCB-H340-MA01/CRB_R01.00/GX/ES/Debug/T0.01` |
| `MX` | MX | `CCB-H340-MA01/CRB_R02.00/MX/ES/Debug/T0.08` |

> ⚠️ 上表后四行（Haier / Lecoo / GX / MX）是从分支命名**位置推断**收录的，未经人工确认。
> 若不是客户（而是项目代号 / 板卡版本），**直接删掉对应行** —— 删掉后遇到该段会转而询问用户。
> 想统一用中文客户名，改成 `Haier=海尔` 这种形式即可。

## 二、非客户关键词表（出现即**不**当客户）

用于把「阶段 / 类型 / 占位符 / 人名」从候选里剔除。

| 类别 | 关键词 |
|---|---|
| 类型 | `Main` `Master` `Dev` `Develop` `Debug` `Release` `Realse`（仓库里有这个拼写） `Pre-Release` `Prerelease` `Test` `Pre` `RC` `migrate` |
| 阶段 | `ES` `MP` `PV` `CS` `SIT` `EVT` `DVT` `PVT` |
| 占位符 | `MAINBOARD` `Mainboard` `Generic` `Default` |
| 人名 / 个人前缀 | `PYH` `TJY` `pyh` `jim`；以及**全小写 2–5 位**的段（脚本内 PERSONAL_RE 单独处理，无需在此穷举） |
| 客户标记段 | `Customer` `Oem` `OEM` `Custom` `定制` `客户` —— **这些段本身不是客户名，它后面那段才是** |

## 三、基线段正则

脚本内 `BASELINE_RE`。兼容两种分隔写法：

- `CRB_R02.03-Pre`
- `CRB_05.72.17.0009`
- `CRB：05.72.05.0006`（全角冒号）
- 单独出现的 `CRB：05.71.44.0003`（无板型段，属解析失败）

---

## 四、版本段正则

脚本内 `VERSION_RE`，忽略大小写：

```
^[VT]\d+(\.\d+)*[a-zA-Z]*(-[A-Za-z0-9_.]+)?$
```

命中示例（全部来自实测分支）：

| 分支段 | 说明 |
|---|---|
| `V0.04` `V0.21` | 常规 |
| `v0.08` | 小写也认 |
| `V0.09a` | 带尾字母 |
| `T0.01` `T0.03` | T 开头（测试版本） |
| `T0.00-XMC` `T0.01-Hpcb` `T0.04-CaseOpen` `T0.01-DDR_SSC` | 带尾部标签 |
| `V0.21-TST26070901` | 带构建号 |

**必须不命中**的干扰项：

| 分支段 | 原因 |
|---|---|
| `Main-Test` | 类型段，别当版本 |
| `migrate` / `Test` / `Pre` | 类型段 |
| `TST26070901` | 构建号，无版本号 |
| `H16240014-532` | 这是 **JIRA 号**，不是版本 |
| `Lecoo` / `MAINBOARD` | 客户/占位符 |
| `CRB_R02.03-Pre` | 基线段 |

## 五、维护提醒

新增客户或发现新命名形态时，**优先加配置，不动流程**：先在这里加一行，再考虑改 SKILL.md。

### 脚本读取本文件的约定（改表时别踩）

`scripts/parse_version_tag.py` 按下面的规则解析本文件，**改表时保持这个结构就能立刻生效**：

| 区段 | 取哪几列 | 说明 |
|---|---|---|
| `## 一、客户白名单` | 每行**前两列**（后面的「出处」列不读） | 单元格里可写多个反引号 token；`段=显示名` 做中文化映射 |
| `## 二、非客户关键词表` | 每行**第一列之后的全部列** | 单元格里每个反引号 token 都收为关键词 |
| `## 三` / `## 四` | **不读** | 正则在脚本里硬编码；改正则要改脚本 |

- 识别依据是 `## 一` / `## 二` 这样的二级标题前缀，**别改这两个标题的编号**。
- 表里用反引号包起来的才会被读到，普通文字是给人看的说明。
- 改完自测：`python scripts/parse_version_tag.py "<某个真实分支名>"`，看 `whitelist_size` / `keyword_size` 有没有变对。

实测基线（2026-09-18）：`whitelist_size=5`、`keyword_size=35`。
