# 8 大确认维度（通俗访谈清单）

> 本文档被 `SKILL.md`「三、工作流 - 阶段 2」引用。每个维度都给出"要确认的要点"和"问用户的白话示例"。示例只是参考，你要根据具体功能调整问法。

### 维度 1：这是个什么功能 / 走不走审批

**要点：**
- 这个功能的数据，是"自己直接填进去"就行，还是"填了要找人批一下才算数"？
- 如果要批：分几步？每步谁说了算？
- 这个功能是一整块信息，还是"一坨主信息 + 下面能展开好几行明细"？明细按什么拆（按部门？按人？按项目？）
- 这个功能是"自己录数据用"的，还是"专门给别人选着用"的基础资料（比如部门清单、项目类型清单）？

**白话问法示例：**
- "这个功能录完就算数，还是得谁点个头才能算数？"
- "要点头的话，分几道关？每道关谁来点？什么情况走快路、什么情况要多走一道？"
- "这页面上是只有一坨信息，还是上面一坨、下面还能一行行加好几条？每行是按什么拆开的？"

### 维度 2：要存哪些信息（每一项都要问细）

**要点：**
- 把这个功能要记录的每一项信息列出来（字段）。
- 每一项：叫什么名字？填的是什么类型的东西（文字？数字？日期？从清单里选？文件？）？
- 数字的话：小数点几位？有没有上限/下限？要不要带单位？
- 哪些是必填（不填不让过）？哪些有默认值（一打开就帮填好的）？
- 从清单里选的：清单是固定的还是另外维护的？

**白话问法示例：**
- "这笔钱保留几位小数？最大能填多少？"
- "哪些是打星号必填的？"
- "'项目类型'是固定那几个，还是另外有个地方在维护这个清单？"

### 维度 3：信息从哪来 / 跟谁有关系

**要点：**
- 哪些信息是"从别处带过来、不用自己手填"的（比如项目名称、部门）？
- 这些信息从哪个地方带？带过来之后能不能改？
- 要不要我建议把某些常被复用的信息（比如"项目类型""币种"）单独拎出来做个"基础资料"，以后别的地方也能选？
- 有没有"一个对多个"的关系（比如一个项目对多条发钱记录）？

**白话问法示例：**
- "'项目名称'是自己手打，还是从已有项目里挑？挑完能不能改？"
- "我建议把'币种'单独做一份小清单，以后所有地方都从这里挑，你同意吗？"

### 维度 4：审批怎么走（只有"要审批"的功能才问）

**要点：**
- 有几道关？每道关谁来点（具体角色 or 具体人 or "发起人上级"这类规则）？
- 在什么条件下走 A 路、什么条件下走 B 路？
- 能不能打回？打回到哪一步？
- 抄送（只看不操作）的人有哪些？
- **同一项信息在不同关卡，是不是要求不一样？**（比如第一步"备注"可不填，到了第二步变必填）--这点和维度 5 强相关，要一起对。

**白话问法示例：**
- "审批分几步？每步谁说了算？"
- "什么情况下要多走一步、什么情况下直接过？"
- "能不能打回？打回到哪一步？"
- "有没有人只是被通知一声、但不用操作的？"

### 维度 5：谁能看到什么 / 能改什么（权限，含前端落地）

**这是重点维度，尤其注意前端落地。**

**要点，分三类：**
1. **行级（谁能看哪些数据）**：有没有人只能看自己的、看不到别人的？有没有人能看全部？有没有"只能看本部门"这种中间情况？
2. **栏级（哪一栏可见/可改/必填）**：对同一个信息项，不同人在不同阶段，是"看不见 / 看得见但不能改 / 可以改 / 必须填"中的哪一种？**逐项、逐阶段问清楚。**
3. **按钮级（谁能点哪个按钮）**：哪些操作只有特定人能点？什么时候能点、什么时候不能点？

**⚠️ 特别强调（针对历史踩坑）：**
> 后端在审批流程里配的"这一步这一栏必须填/看不见"规则，**在自定义开发的详情页面上必须真实生效**，不能后端配了、页面却不管。
> 所以这里每一条规则，都默认"前端详情页要按这个真实控制"，并把它写进需求文档，让做页面的人照着实现。

**白话问法示例：**
- "有没有人只该看到自己的数据、看不到别人的？"
- "'实际金额'这一栏，在录的时候谁能看到？谁能改？到了审批那一步，是变必填了，还是不让动了？"
- "'删除'按钮是不是不是谁都能点？什么时候该藏起来？"

### 维度 6：详情页打开来长什么样、怎么交互

**要点：**
- 详情页打开来，上面这些信息怎么摆？一块块卡片叠着，还是分几个页签切换？
- 能一行行加的明细，在页面上是排成表格，还是别的样子？
- **联动**：填了这一项之后，有没有别的项会自动跟着变（比如选了项目，自动带出项目金额）？有没有的项会因为别的项变了而出现/消失/变成必填？
- **只读/可改的切换**：在什么情况下整页变成"只能看不能改"？
- 有没有什么特殊的展示要求（比如某个金额要大字显示、某块信息要折叠起来）？

**白话问法示例：**
- "详情页打开来大致长什么样？要不要分成几个页签？"
- "选了项目之后，会不会自动把一些信息带出来？"
- "什么时候这个页面就锁住只能看了？"

### 维度 7：列表和查询

**要点：**
- 列表上要显示哪几栏？默认按什么排？
- 能按哪些条件筛？（尤其"状态"--状态到底以哪个为准：是看流程走到哪一步的名字，还是看某个自己填的字段？这个一定要问清楚，否则做完发现筛选口径不对要返工）
- 要不要分页？每页多少条？
- 要不要能导出成表格文件？

**白话问法示例：**
- "列表上要看到哪几栏？"
- "能按什么筛？状态这个怎么显示、按什么筛？"
- "要不要能导出？导出成什么样子？"

### 维度 8：复杂业务逻辑（不限于按钮，含联动/渲染/计算/拆分）

**要点：**
- 有没有"点一下，系统自动生成一堆东西"的逻辑？生成出来按什么拆？
- 有没有自动计算（比如几行明细自动汇总到某个合计）？汇总规则？
- 有没有"根据某个值，页面显示成不一样样子"的渲染逻辑？
- 有没有"改了 A，B 自动跟着变"的联动（和维度 6 的字段联动可能重叠，这里更侧重多步骤/跨页面的逻辑）？
- 任何这类逻辑都要问清三件事：**触发条件 -> 处理规则 -> 结果长什么样**。

**白话问法示例：**
- "有没有'点一下自动生成'的功能？生成出来按什么拆？拆完还能不能改？"
- "这几行明细填完，上面那个合计会不会自动算？怎么算的？"
- "在什么情况下，这个页面会显示成和平时不一样的样子？"

> 💡 这 8 个维度是"参考但不限于此"。聊的过程中如果发现功能还有没覆盖到的特殊点，**主动新增确认项**，不要硬塞进这 8 个里就完事。
