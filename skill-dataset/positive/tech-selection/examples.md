## 五维关键论据（示例写法）

- **长期维护**：商业公司 7 年持续 + 千万级周下载 + n8n/Langflow 生产背书 vs 企业兼职投入 + 1.x 曾停滞、2.0 重写级升级 → 4.5 vs 3.5
- **研发投入**：画布 20 vs 30 人日（分工作项对比表）；**桥接税随迭代线性放大**（RF 新节点=写组件，LF 每个富交互卡片过一次 HtmlNode 桥接）→ 4.5 vs 3.0
- **可扩展性**：扩展=「再写一个 React 组件、共享同一份受控 state」 vs SVG/HtmlNode 双轨 + 跨框架状态同步 → 5.0 vs 3.5
- **能力与场景**：公道话——论通用图编辑广度 LF 更全（BPMN/泳道/脑图/ER），但均为**无效供给**；有效需求项（视口受控/组件化卡片/只读复用）RF 占优 → 4.5 vs 3.5（通用口径 4.0 vs 4.5 已注明）
- **性能与体积**：65KB vs 100~150KB gzip；百节点规模双方富余 → 4.5 vs 4.0

## 可复用的表达范式

- 无效供给句式：「候选方 X 通用能力更全（如实列出），但本项目需求射程是 Y，这些能力构成理解与裁剪成本而非优势。」
- 共同短板句式：「自动布局两方均不提供，由自有 core 实现，属业务层能力，不构成区分项。」
- 反选通道句式：「出现以下任一情况应反选：…；本项目零命中，反选通道关闭，二选一成立。」
- 公道话句式：「先说公道话：论 XX 能力，落选方反而更全…但…」
