# 推荐复现项目选型

> 课题：AI Agent 技能（Agent Skills）全链路安全审计与效果评估系统
> 数据日期：2026-11-16（Star 数为 shields.io 实时值，可能变化）
> 详细对比依据：[agent-skill-project-comparison.md](./agent-skill-project-comparison.md)

## 一、选型结论

**主复现基线 = NVIDIA SkillEvaluator（评估框架）+ NVIDIA SkillSpector（安全扫描器）**

两者同为 NVIDIA 官方维护、star 数断层领先、且天然协同（SkillSpector 就是 SkillEvaluator Tier 1 的配套扫描器），是唯一"官方维护 + 高采用 + 文档完整 + 三层能力互补"的组合。

## 二、选型理由（对照课题三层需求）

| 课题核心要求 | 对应能力 | 复现项目 |
|---|---|---|
| ① 静态质量与安全扫描 | 静态规则 + 质量评分 + 投毒/注入/凭证/后门检测 | SkillSpector（扫描）+ SkillEvaluator Tier 1 |
| ② 模型驱动深度安全审计 | 可选 LLM 语义层，识别静态规则漏报 | SkillSpector 两段式（fast static + optional LLM） |
| ③ 语义去重 / 冗余冲突识别 | embedding 相似度检测重复指令与 catalog 重叠 | SkillEvaluator Tier 2 |
| ④ 实时沙盒评估（行为增益量化） | Harbor/Docker 沙盒中"带/不带 Skill"对照，量化 Skill Lift | SkillEvaluator Tier 3 |
| ⑤ 安全审计报告输出 | JSON / Markdown / SARIF | 两者均支持 |

## 四、需自研的空白能力（全行业无现成实现）

以下两项在已调研的 12 个项目中**全部缺失**，必须基于 SkillEvaluator 自行开发：

| 空白能力 | 课题要求 | 自研落点 |
|---|---|---|
| **F6 冗余 Skill 推荐 + 联网搜索** | 阶段二：识别冗余冲突后向用户推荐更优 Skill，可联网搜索 | 挂接在 SkillEvaluator **Tier 2 语义去重结果**之上，自建推荐层 + 联网搜索接口 |
| **F9 自动修复** | 阶段四加分项 | 参考 SEG 的"检测→定位→修复"闭环思路实现 |

## 五、复现落地路线（对应 TODO 阶段）

1. **阶段一（环境搭建）**：安装 SkillEvaluator + SkillSpector 依赖 → 配置 Docker/Harbor 沙盒 → 配置 LLM API Key → 跑通官方基准示例。
2. **阶段二（三层实战）**：自建 3 个测试 Skill（正向 / 冗余冲突 / 恶意靶场）→ 分别验证 Tier 1 拦截、Tier 2 去重、Tier 3 增益 → 自研 F6 推荐功能。
3. **阶段三（工程化）**：
   - 任务 A：在 SkillSpector / skill-auditor 的规则机制上新增 ≥2 条企业规则（非白名单域名 curl/wget、禁止读 `~/.ssh`/`.env`）。
   - 任务 B：编写 Python CLI 一键批量扫描 → 过滤高危 → 输出 Markdown/HTML 综合审计报告。
4. **阶段四（加分项）**：参考 SEG 实现 Skill 问题自动修复。

## 六、风险与注意事项

- **Star 数据波动**：skill-auditor 等 npm/PyPI 包无 GitHub star，应以下载量衡量。
- **规则扩展需实测**：SkillSpector 的自定义规则机制（S7）在选型表中标为 △，落地任务 A 前需先验证其扩展接口；若扩展性不足，改用 skill-auditor 的 YAML 规则引擎。
- **沙盒成本**：Tier 3 需配置 Agent、模型与 Docker 沙盒，会产生 LLM API 费用；Mac 环境需提前确认 Docker Desktop 及 Harbor 依赖。
- **结论不合并**：安全扫描、语义去重、效果增益是三类独立结论，报告中应分别记录，不合并为单一分数。
