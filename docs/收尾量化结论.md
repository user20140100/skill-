## 一、security → flag 审计结论（Tier1）

### 1.1 自定义规则开关对照（任务 A 核心量化）

规则 B（`cvte_credential_inline.yar`，明文凭证内嵌命令行/连接串）对同一 skill 的「占位符 → 明文」恶意化改造，挂载前后 Tier1 结果对照（完整数据见 `deliverables/03-现场演示与复盘/规则B证实报告.md`）：

| 样本 | 不挂规则 B（baseline） | 挂规则 B（withb） | Δ |
|---|---:|---:|---|
| c-dev 原文（占位符 `<pw>`） | 58 分 / 4 findings | 58 分 / 4 findings | **0（零误报）** |
| c-dev 恶意化（明文 `CVTE@2026`） | 58 分 / 4 findings | **69 分 / 5 findings** | **+11 分 / +1 finding** |

- 恶意化样本中，明文凭证行 `echo 'root:CVTE@2026' | chpasswd` 在不挂规则 B 时被内置 71 条规则**整行漏报**（内置 PE3 只盯「读取敏感凭证文件路径」，YR1 只盯「写公钥持久化」，无一条落在明文密码上）；挂规则 B 后新增 1 条 `YR1(cvte_credential_chpasswd)` 命中，风险分 58 → 69。
- 占位符样本两臂结果一致，证明规则 B **对显式占位符（`<pw>`）不误报**。

### 1.2 靶场 Skill（custom-rules-range）Tier1 结果

规则 B 六类凭证载体 + 外发样本的综合扫描（`range-scan.json`）：

| 指标 | 值 |
|---|---|
| risk_score | **59** |
| severity / recommendation | **HIGH / DO_NOT_INSTALL** |
| findings 总数 | **12** |

findings 构成：

| 规则 | 类别 | 严重度 | 命中数 | 说明 |
|---|---|---:|---|---|
| YR1（`cvte_credential_*`） | 明文凭证 | HIGH | **7** | 规则 B：chpasswd / curl -u / mysql -p / psql 连接串 / redis -a / mongosh / URL userinfo 全命中 |
| E1（External Transmission） | 数据外发 | MEDIUM | **4** | 发往非白名单域名 `evil-c2.example.com` 的 curl / requests.post |
| LP3（MCP Least Privilege） | 过度授权 | MEDIUM | **1** | skill 未声明工具作用域 |

> 结论：规则 B 的 7 个正样本（8 类凭证载体）**全部命中 HIGH**，负样本（`-p<password>`、`-u ${password}`、`-p` 无值、`os.environ` 取凭证）**零命中**，实现「明文凭证内嵌」这一确定性检测盲区的补盲。

### 1.3 域名白名单放行（抑制层扩展）

- 落点：`baseline.yaml` 的 `allow_domain: ["*.cvte.com", "*.gz.cvte.cn"]`（精确 host + `*.` 子域名通配），经 `--baseline` 挂载到 SkillSpector 抑制层，在评分与去重前把「发往白名单域名」的外发 finding 移入 `suppressed`（含 `reason` 审计留痕）不计分。
- 职责分离：检测归检测（规则 B + 内置 E1）、放行归放行（抑制层 `allow_domain`），白名单对内置 E1 等所有外发 finding 一律生效，避免放行逻辑只对某一条规则生效。
- 规则开关（灰度控制）：`custom-rules/select.yaml` + `toggle.py` 提供 `rule_a`（白名单放行）/ `rule_b`（凭证检测）两个**独立开关**，4 组合（无 / 仅 A / 仅 B / A+B）可现场勾选 → 重跑 → 对比启用前后 findings 差异。

### 1.4 批量审计高危过滤（任务 B）

批处理 CLI 对 `library-demo` 目录 5 个 skill 的 Tier1 综合审计（`--llm`，`reports/audit-llm.md`）：

| Skill | 安全评级 | 风险分 | 高危 finding | C/H/M/L |
|---|---|---:|---:|---|
| `es-log-query` | **高危** | 87 | 15 | 0/12/11/19 |
| `android-log-analysis` | **高危** | 53 | 4 | 0/2/7/11 |
| `code-review` | **高危** | 0 | 1 | 0/1/5/10 |
| `calculator` | 安全 | 0 | 0 | 0/0/6/7 |
| `requirement-spec` | 安全 | 0 | 0 | 0/0/5/17 |

- **flag 过滤规则**：`SkillSpector HIGH/CRITICAL` 或 `Tier1 critical/high > 0` → 进「高危风险项」，`verdict == unsafe`。5 个 skill 中 **3 个 flag 为 unsafe、2 个 safe**。
- `es-log-query` 为最高危样本：静态风险分 36（8 findings）经 LLM 语义分析升至 87（15 findings），高危项由 8 → 15，暴露「读 `.env` 凭证 + 明文 Basic Auth 传 ES 密码 + 禁用证书校验」等行为与描述不符的语义风险。

## 二、redundant → dup 结论（Tier2 语义去重）

| 正向 skill | 命中 catalog skill | 相似度 | 分类 |
|---|---|---:|---|
| `calc-pro`（正向） | `calculator`（冗余） | **0.9129** | **HIGH_SIMILARITY** |

- **阈值与判定**：Tier2 `similarity-check` 以 embedding（bge-m3，dim 1024）对 skill 描述向量化，`score ≥ 0.75` 进入候选；`HIGH_SIMILARITY` 即冗余对成立，触发后续推荐链路。
- **冗余对构成**：`calc-pro`（专业计算套件，算术 + 统计 + 财务）与 `calculator`（官方计算器，仅算术 + 单位换算）在「基础算术 + 单位换算」能力上高度重叠，构成一组可复现的冗余冲突对。
- 冗余数据集共 **30 个 / 8 组**（git 提交、代码审查、测试用例、需求分析、飞书文档、专利、Jira、日报等语义重叠组），用于验证 Tier2 对语义重叠的拦截能力。

## 三、positive → pass_rate_gain / Lift 结论（Tier3 沙盒增益）

### 3.1 正向 Skill（calc-pro）专项任务增益

对 calc-pro 专项用例（统计 + 财务，3 case）跑 with/without 双臂对照（run_id `20261118_094110_1_8140f4ce351c`，agent=opencode，model=openai/qwen3.8-flash）：

| 指标 | baseline（无 skill） | with calc-pro | 增益 |
|---|---:|---:|---:|
| **Overall** | 68.2% | **100.0%** | **+31.85 pp** |
| **Pass@1（goal）** | 0.0% | **100.0%** | **+100 pp** |
| Effectiveness（有效性） | 11.1% | 100.0% | +88.9 pp |
| Correctness（正确率） | 93.3% | 100.0% | +6.7 pp |

- **Skill Lift = +0.3185（+31.85 个百分点）**；二次复测（run_id `20261118_114431_1_266ece03707b`）lift +0.2963、Overall 70.4%→100%，方向一致。
- **增益结构**：增益几乎全部来自 **Effectiveness（+88.9 pp）**——goal/behavior 定义为「按 calc-pro 的 `stats.py`/`finance.py` 工作流计算」，skill 存在时工作流被精确执行（goal_accuracy 0→1、behavior 0.22→1.0）；Correctness（+6.7 pp）为技能对最终数值答案的真实增量。
- **资源代价（报告型，不计分）**：带 skill 多花 token +38%（76,100 vs 55,318）、多 2 轮，但墙钟耗时 ↓14%（36.6 s vs 42.6 s）——以「更多 token + 更多轮数」换取「更快墙钟 + 可复现、可审计的确定性计算路径」。

### 3.2 冗余对（calc-pro vs calculator）共享任务增益

公共用例 `shared/arithmetic`（9 个基础算术 + 单位换算，两者能力交集）横向对比（run_id calc-pro `…133129…` / calculator `…133911…`）：

| 维度 | calc-pro | calculator | 更优 |
|---|---:|---:|---|
| goal_accuracy | 1.0 | 1.0 | —（持平） |
| prompt_tokens（输入） | 75,358 | **71,439** | calculator |
| completion_tokens（输出） | 349 | **256** | calculator |
| duration_seconds（耗时） | 414.6 | **339.7** | calculator |
| rounds（轮数） | 12 | 12 | —（持平） |

- **增益结论**：结果等效（goal_accuracy 均 1.0）下，`efficiency_better → calculator`（更省 token、耗时更短）。
- 两者 Tier1 安全均 `safe`（SkillSpector score 0 / LOW / 0 issue；Tier1 high=0），安全轨打平，无需从安全角度二选一。

### 3.3 公司库 Skill 的零增益样例（changelog）

除自建正向 skill 外，对公司库实际 skill 也跑了 Tier3 增益评估，发现**公司库中的 skill 存在不能带来增益的情况**：

- **被测 skill**：`changelog`（公司库 `skills.gz.cvte.cn`，author fujinxiang，v1.0.1），能力「基于 Git 提交记录自动生成中文 changelog」。
- **run**：`20261117_105404_1_e61235fdd49f`，agent=opencode，model=`openai/qwen3.8-max`，1 个正向 case（provisional）。

| 指标 | baseline（无 skill） | with changelog | 增益 |
|---|---:|---:|---:|
| **Overall** | 100.0% | **100.0%** | **±0.0** |
| **Pass@1** | 100.0% | 100.0% | ±0.0 |
| Correctness（正确率） | 100.0% | 100.0% | ±0.0 |
| Effectiveness（有效性） | 100.0% | 100.0% | ±0.0 |
| Discoverability（可发现性） | N/A | 97.5% | 不可比 |
| Efficiency（效率） | N/A | 97.1% | 不可比 |

- **Skill Lift = +0.0000（零增益）**：带 skill 与 baseline 均 100% 达成（completed agent score 98.91%），token 反而 **+33.3%**（323,055 vs 242,281）。
- **解读**：changelog 属于「流程/描述型」需求 skill——对强模型（qwen3.8-max）而言，「读 git log 生成中文 changelog」这类任务 baseline 即可独立完成，skill 未带来可测增量，只增加 token 成本。这与前期「4 个 G4 需求类 skill 的 Tier3 增益均中性/负向」的结论一致，说明公司库中确实存在**不加增益、只加成本的 skill**。

## 四、三层综合结论（收尾）

| 层 | 数据集组 | 结论类型 | 核心量化结果 |
|---|---|---|---|
| **Tier1 安全** | security | flag | 规则 B 补盲明文凭证（58→69 分、+1 finding，占位符零误报）；靶场 12 findings / HIGH / DO_NOT_INSTALL；批量审计 5 个 skill 中 3 个 unsafe（es-log-query 风险分 87 最高） |
| **Tier2 去重** | redundant | dup | calc-pro ↔ calculator 相似度 **0.9129 HIGH_SIMILARITY**，冗余对成立 |
| **Tier3 增益** | positive | pass_rate_gain / Lift | calc-pro 专项 **Lift +0.3185**（Overall 68.2%→100%，Pass@1 0%→100%）；冗余对共享任务 calculator 效率更优；公司库 changelog **Lift +0.0000 零增益**（token +33.3%） |

**一句话总结**：

> 三层评估对三组数据集分别给出了可量化的独立结论——安全层（Tier1）用自定义规则补上「明文凭证内嵌」盲区并据此 flag 出 3 个高危 skill；去重层（Tier2）以 0.9129 的高相似度识别出 calc-pro/calculator 冗余对；增益层（Tier3）测出正向 skill 对特化任务 +31.85 pp 的 Lift、冗余 skill 对泛化任务的效率优势，同时也揭示公司库中存在 changelog 这类「零增益、只加 token」的 skill——三者互不替代，共同构成「扫得全、去得净、评得准」的全链路审计闭环。
