# 静态原型输入：反向提取 + 缺口追问

> 被 `SKILL.md` 的入口分流引用。当输入是一份**静态原型**（HTML 文件 / 截图 / 设计稿）时，先按本节**反向提取原型能回答的信息**，再把"看不见的逻辑"挑出来追问。原型是"长什么样"，不是"规则是什么"——千万别把页面样子当成完整需求。

## 核心思路

原型能直接"看到"的东西（字段、布局、按钮、列表栏），几乎不用问；原型"看不到"的东西（审批、权限、联动、计算、数据来源），必须逐条追问。把访谈精力全放在看不见的地方。

## 第 1 步：读取原型

- **HTML 文件**：读源码，提取——有哪些页面、每个页面有哪些信息项（从 label / 输入框类型推断类型）、布局（卡片 / 页签 / 分栏）、能不能一行行加明细、有哪些按钮、列表页显示哪几栏。
- **截图 / 图片**：用图像分析工具识别上述内容。
- **多个文件 / 页面**：先建索引（页面清单），再逐页提取。

## 第 2 步：按维度标注"原型能回答多少"

| 维度 | 原型可见性 | 说明 |
|---|---|---|
| 维度 1 功能边界 | ⚠️ 部分 | 页面结构看得到，但"走不走审批"看不到 |
| 维度 2 要存哪些信息 | ✅ 大部分可见 | 字段名、输入类型从控件能看出来 |
| 维度 3 信息从哪来 | ⬜ 看不见 | 下拉框的数据从哪来、能不能改，原型不说 |
| 维度 4 审批怎么走 | ⬜ 看不见 | 完全藏在 UI 后面 |
| 维度 5 权限（行/栏/按钮） | ⬜ 看不见 | 谁能看/改/点，原型不体现 |
| 维度 6 详情页布局/明细 | ✅ 可见 | 原型的核心价值 |
| 维度 7 列表与查询 | ✅ 大部分可见 | 显示栏/筛选框看得到（但状态口径看不见） |
| 维度 8 联动/计算/渲染 | ⬜ 看不见 | UI 也许有暗示，但触发规则/计算公式未知 |

## 第 3 步：先和用户对齐"看到的"

把从原型提取出来的字段清单、布局、列表栏，用大白话复述给用户："我从原型里看到这些信息项、这样摆、列表显示这几栏，对吗？"得到"对"再往下。**这一步能避免把原型的笔误 / 占位当成真实需求。**

## 第 4 步：把 ⬜ 汇成缺口清单，集中追问

把第 2 步所有 ⬜（和 ⚠️ 里看不到的部分）汇成一张"待问清单"，逐条用大白话问（问法见 [dimensions.md](dimensions.md) 对应维度）。原型已 ✅ 的不再重复问。

## 产物

需求文档写到 `<项目根>/docs/requirements/<功能名>.md`（模块里的功能则写到 `<模块名>/<功能名>.md`）。原型已回答的维度（2 / 6 / 7）直接填入，追问出来的补进其余章节。文档里建议加一句"本功能字段 / 布局依据原型 `<原型文件名>` 提取"，方便回溯。

## 注意

- **原型 ≠ 规格**：页面长这样，不代表背后的审批 / 权限 / 联动就是这样。任何"看不见"的，都要问，不能凭原型猜。
- **占位文字别当真**：原型里的"请输入""测试数据"这类是占位，不是真实字段含义。
- 全程仍遵守 `SKILL.md` 的零术语话术规则。
