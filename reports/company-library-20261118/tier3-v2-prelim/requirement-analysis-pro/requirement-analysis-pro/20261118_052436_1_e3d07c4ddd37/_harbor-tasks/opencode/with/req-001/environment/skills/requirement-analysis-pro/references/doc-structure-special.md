# 专项需求文档结构

> 适用于围绕一个明确业务结果、涉及多个模块或系统的专项，以及由风险升级的存量改造。先读取 [`doc-structure-common.md`](doc-structure-common.md)。

## 1. 默认目录

```markdown
# <专项名称>需求说明书

## 1. 痛点与目标

## 2. 范围与优先级
### 2.1 本期范围（MVP）
### 2.2 本期不做（后置）

## 3. 业务解决方案
### 3.1 业务解决流程图
### 3.2 数据关系图（按需）
### 3.3 系统边界图（按需）

## 4. 系统功能
### PAGE-xxx / JOB-xxx / INT-xxx
#### FR-xxx｜【新增/修改/删除/待确认】【P0/P1/P2】<功能名称>

## 5. 跨功能公共要求（按需）

## 6. 待确认项（存在时）

## 附录：术语与缩略语（按需）
```

## 2. 范围与优先级

按共用规范列示本期 MVP 与后置项；P1 仅在支撑 P0 闭环时进入 MVP。

## 3. 业务解决方案

- 只输出用于统一理解的业务解决流程图。
- 对象关系复杂、责任源或主从关系影响方案时，增加数据关系图。
- 跨系统责任、输入输出或集成方向影响评审时，增加系统边界图。
- 图后只写必要说明；场景、规则、字段、状态和异常进入对应功能。
- 简单专项如果没有跨页面或跨系统流程，可以省略本章，直接进入系统功能。
- 流程图后不再逐步复述相同内容。

## 4. 系统功能

- 以页面和真实运行载体为主线，只写本专项新增、修改、删除、受影响不变和待确认功能。
- 每个 `FR-xxx` 按需说明原功能、本次功能、不变边界、影响、功能行为、页面字段、后台信息、对象规则及待确认项。
- 字段和后台处理信息就地说明，不默认建立数据对象章节。
- 同一对象的规则集中说明，简单规则不编号。
- 状态机、异步和异常闭环只有在主对象确有相关机制时才输出。
- 用户要求精简时，每个功能通常保留 3～8 条关键行为；原始材料未提出的口径、字段和规则不主动穷举。

## 5. 跨功能公共要求

只有同一要求覆盖多个功能或存在专项风险时才输出，例如：

- 公共接口或事件契约；
- 跨页面权限和数据范围；
- 可测的性能、安全、可用性要求；
- 历史数据初始化或回填；
- 调度、监控、告警、接管、回滚和对账。

无变化时不保留“沿用原机制”的空章节。

待确认项按“数据来源与口径、计算规则、责任与权限、运行方式”等决策主题合并。一个主题使用一个 `Q-xxx`，正文已经就地说明时不再建立重复汇总表。

## 6. SDD与验证

- `FR-xxx` 是主追踪编号。
- 普通专项不默认生成测试用例和追踪矩阵。
- 用户要求开发、测试或 SDD 包时，将可独立交付的 `FR` 组合成开发切片。
- 高风险规则、状态、接口和异步功能应提供验证要点；需要正式追踪时再使用 `AC-xxx` 和 `TC-xxx`。
