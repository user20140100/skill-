# 项目型需求文档结构

> 适用于新平台、跨业务域、多核心系统协同、端到端业务变革、重要迁移或分阶段推广。先读取 [`doc-structure-common.md`](doc-structure-common.md)。

## 1. 默认目录

```markdown
# <项目名称>需求说明书

## 1. 痛点与目标

## 2. 范围与优先级
### 2.1 本期范围（MVP）
### 2.2 本期不做（后置）

## 3. 业务解决方案
### 3.1 端到端业务解决流程图
### 3.2 数据关系图（按需）
### 3.3 系统边界图（按需）

## 4. 系统功能
### <系统/模块>
#### PAGE-xxx / JOB-xxx / INT-xxx
##### FR-xxx｜【新增/修改/删除/待确认】【P0/P1/P2】<功能名称>

## 5. 跨功能公共要求（按需）

## 6. 实施分期与待确认项（按需）

## 附录：术语与缩略语（按需）
```

## 2. 项目级要求

### 2.1 痛点与目标

仍使用“痛点、目标、备注”三列表格。备注写范围外事项、组织差异、阶段限制或待确认内容。不单独展开长篇现状、愿景和价值分析。

### 2.2 范围与优先级

按共用规范列示本期 MVP 与后置项。实施分期以优先级和依赖关系为依据，但版本安排不得仅由优先级机械推导。

### 2.3 业务解决方案

按评审需要输出：

- 端到端业务解决流程图：说明起点、主要阶段、关键控制和结果；
- 数据关系图：说明关键业务对象及责任源，不展开数据库表；
- 系统边界图：说明核心系统、上下游系统、对象或事件流向。

场景、规则、状态、异常和页面操作不在本章重复，进入相应功能。

### 2.4 系统功能

- 按系统/模块、页面或运行载体和 `FR-xxx` 组织。
- 一个页面有多个功能时先给页面功能表，再逐项展开。
- 字段、后台保存信息和对象规则就地说明。
- 无页面的接口、任务、批处理、规则引擎和 Agent 不创建页面。
- 存量修改仍使用原功能、本次功能、明确不变和修改影响四段式。

### 2.5 跨功能公共要求

项目型需要完整检查，但不是全部输出。仅在确有公共变化、复杂依赖或上线风险时增加：

- 数据责任和跨系统同步；
- 接口、事件和上线顺序；
- 跨模块权限和审计；
- 可测 NFR；
- 迁移、初始化、灰度、回滚、监控和运营；
- 多组织推广、版本兼容和分阶段实施。

功能特有内容留在功能块，不在公共章节重复。

### 2.6 术语

术语与缩略语放在附录。只有原始需求明确使用专有名词、缩写或存在跨组织口径差异时才输出。

## 3. SDD切片

大型项目先按可独立交付的业务结果拆分开发切片。每个切片引用一个或多个稳定 `FR-xxx`。未要求开发规格时只说明建议分期，不生成 `spec.md`、测试用例和追踪矩阵。
