## 2. Tier 1：静态质量与安全审计

### 2.1 方法

Tier1 共 14 个校验器：Schema、SemVer、Security Scan、PII、License、Code Risk、Secrets、Integrity、Dependency Vuln、Unicode Smuggling、QUALITY、SCRIPT_LINT、Harness Compatibility、RUBRIC_EVAL（LLM-as-Judge，9 条标准，单条门槛 7/10）。Security Scan 内部串联：

1. SkillSpector 静态 YARA 规则扫描（`skillspector`）
2. SkillSpector LLM 语义分析（`skillspector-llm`）
3. 对每条 finding 做 LLM 复核（区分 true/false positive）
4. Gitleaks 密钥扫描

### 2.2 text-analyzer：整体 FAIL（真实质量缺陷）

| 项目 | 结果 |
| --- | --- |
| 校验器执行 | 14/14，0 incomplete |
| 通过检查数 | 11/12（1 failed，2 N/A） |
| 质量分 | **88.8/100（B）**：correctness 75 / discoverability 95 / reliability 95 / efficiency 100 |
| Rubric 总分 | **74.5/100**（FAIL） |
| 失败项 | `trigger_simulation` **6/10 < 7** |
| 安全扫描 | **PASS**——静态 + LLM 语义完成，2 条 MEDIUM「MCP Least Privilege」，LLM 复核为 true positive |
| 问题分布 | high 1 / medium 7 / low 12 |

**分析：** `SKILL.md` 的 description 混入了 "summarize" 等宽泛能力描述，LLM 判官在模拟 5 个触发场景时认为它会"在非目标请求上被触发"。这是可复现的触发准确性问题；其余标准（描述清晰度 8、示例质量 8、范围界定 7、错误处理 7）均在及格线上。安全扫描的两条 MEDIUM 属"未声明 permissions"的最小权限建议，不是漏洞。

### 2.3 calculator：整体 PASS

| 项目 | 结果 |
| --- | --- |
| 校验器执行 | 12/12 完成，0 failed / 0 incomplete |
| 质量分 | **87.5/100（B）**：correctness 75 / discoverability 90 / reliability 95 / efficiency 100 |
| Rubric 总分 | **80.5/100**（PASS） |
| 安全扫描 | PASS（`security done in 136.3s`） |
| 问题分布 | high 0 / medium 4 / low 13（全部建议级） |

**说明：** 首次运行时 `security` 步骤 166.9s 后以 `incomplete: skillspector` 结束，导致整体 INCOMPLETE、退出码 1；重跑后 136.3s 正常完成。属于网关/扫描器瞬态超时，非技能缺陷。

## 3. Tier 2：语义去重与冗余检测

### 3.1 集合级（inter-skill）

| 指标 | 结果 |
| --- | --- |
| 入选 / 索引 / 跳过 | 6 / 6 / 0 |
| 阈值 | 0.75 |
| 重复对 | **0** |
| Catalog | `02-tier2/inter-skill/official-catalog.json`（6 条，供后续比对） |

### 3.2 skillevaluator 单技能内部（intra-skill）

| 指标 | 结果 |
| --- | --- |
| 文件数 / chunk 数 | 10 / 38 |
| 聚类阈值 | 0.80 |
| 候选簇 | 3 组，最大相似度 0.850 / 0.813 / 0.809 |
| LLM 裁决 | 3 组全部 `RELATED_BUT_DISTINCT`（置信度 0.88 / 0.88 / 0.91） |
| 判定 | PASS（无需要合并的冗余） |

**分析：** 官方 skillevaluator 技能含 9 个 reference 文档、内容同属"如何调用评估器"，语义接近但职责不同（用法、报告、排障等），去重器正确识别为"相关但不同"，未误报——这是 Tier2 的关键价值：区分"高相似"与"真重复"。

### 3.3 calculator 单技能复核

| 指标 | 结果 |
| --- | --- |
| Context Deduplication | 2 文件 / 8 chunk，无冗余（阈值 0.8） |
| Similarity Check | 载入 6 条 catalog，与其余 5 条比对，无 ≥0.75 匹配 |

**结论：官方示例之间、单个官方技能内部都不存在冗余或冲突。** 与自建 `redundant` 数据集（30 个技能、多组 0.75+）形成对照，说明去重器既能识别冗余，也不会对"高相似但不同"误报。

## 4. Tier 3：Docker 沙盒 A/B 行为评估

### 4.1 设置

- 用例：`calculator-001` —— "What is 2 + 3 * 4? Please use the calculator skill to compute this."
  - 期望：读取 SKILL.md → 执行 `calc.py` → 返回 14
- Agent：`opencode` 1.19.5；模型 `openai/qwen3.8-flash`（judge 同模型）
- 两臂：with-skill / baseline（同用例、同容器镜像、各自独立 Docker 沙盒）
- 1 case × 1 attempt × 2 arms，`--timeout-multiplier 3`

### 4.2 结果（`03-tier3/calculator/20261117_234710_1_fe25371abd9e/`）

| 维度 | baseline | with-skill | 差值 |
| --- | ---: | ---: | ---: |
| Overall | 0.7222 | **1.0000** | **+0.2778** |
| Security | 1.0 | 1.0 | ±0 |
| Correctness（accuracy） | 1.0 | 1.0 | ±0 |
| Discoverability（skill_execution） | N/A | 1.0 | — |
| Effectiveness = ½(goal + behavior) | 0.1666（goal 0 / behavior 0.333） | 1.0（goal 1 / behavior 1） | +0.833 |
| Efficiency（skill_efficiency） | N/A | 1.0 | — |
| Pass@1（Overall ≥ 0.5） | 0% | 100% | +100pp |
| Token 用量 | 7,479 | 23,847 | +218.8% |

执行质量：两臂各 1 次有效评分，**0 执行失败、0 判官失败**；with-skill 首轮命令全成功（error_recovery=1.0）。

### 4.3 证据链

- **with-skill**：`skill_execution` 显示 "Activated via Skill tool: calculator"、"Executed calc.py"、"Correct workflow order"；`skill_efficiency` 显示只路由到 calculator、按 workspace 读文件。
- **baseline**：模型直接口算出 "14"，但明确说 "There's no calculator skill available; computed directly"；`accuracy=1.0`，`goal_accuracy=0.0`、`behavior_check=0.333`，判官理由为"答案正确但没有执行 calc.py / 未使用 skill 的证据"。

### 4.4 如何解读 +27.8 分

1. **答案正确性没有增益**：两臂 accuracy 都是 1.0——这道题 baseline 心算就能对。
2. 增益全部来自 **effectiveness（goal_accuracy + behavior_check）**：而该用例的 ground truth 明确要求"必须读取 SKILL.md 并执行 calc.py"，baseline 天然无法满足。这是**测量口径导致的 +1.0**，不是真实能力提升。
3. 因此：官方示例的 Tier3 价值在于**验证流水线能检测技能发现、激活、脚本执行、工作流顺序、错误恢复**，而不是"量化真实行为收益"。要测量真实增益，必须设计 baseline 单独做不到的 eval case（例如依赖技能内置领域数据/脚本的复杂计算或转换）。
4. **成本信号**：with-skill token 用量是 baseline 的 3.2 倍——技能调用有明确开销，Tier3 把它作为报告指标（不计分）。

## 5. 三层如何协同

| 层 | 回答的问题 | 官方示例上的证据 |
| --- | --- | --- |
| Tier1 静态 | 技能"能不能用、安不安全" | text-analyzer 的 trigger 缺陷；两技能的 MCP 最小权限建议；密钥/依赖/许可证全部通过 |
| Tier2 语义 | 技能之间/内部"是否冗余冲突" | 6 个官方技能互不重复；skillevaluator 内部 3 组高相似被判"相关但不同"（不误报） |
| Tier3 沙盒 | 实战中"是否被发现、被正确调用、有没有用、代价多大" | with-skill 全维 1.0、激活+执行证据齐全；baseline 答案对但目标/流程不达标；token +218.8% |

三者形成递进证据链：Tier1/Tier2 是**离线、低成本、可批量**的门禁；Tier3 是**在线、高成本、接近真实**的验收。官方示例的定位正是"证明三层能工作"，本报告数据支持这一点。

## 7. 局限与下一步

1. **数据集规模**：Tier3 仅 1 个 case、1 次尝试，pass-rate 置信区间 ±0.40（SkillEvaluator 判定为 "provisional"）。要出可发布结论需 ≥10 个 case + 负例（`expected_skill: null`）。
2. **真实增益未量化**：官方 calculator 用例把"必须用技能"写进 ground truth，baseline 必然 0 分；真实行为增益应视为 0。应补充"baseline 单独做不到"的用例。
3. **token 成本**：技能激活带来约 3 倍 token 消耗，需在业务侧权衡。
4. **网关/扫描器稳定性**：calculator Tier1 首次 security 超时、Tier3 构建网络问题均为环境因素；正式评估建议固定镜像与预构建依赖（见第 8.3 节）。

### 8.2 失败轮次原因（备查）

| 运行 | 原因 |
| --- | --- |
| 173213 | BuildKit 解析镜像源 `docker.m.daocloud.io` 失败（`python:3.12-slim` 元数据） |
| 174844 / 211416 / 222053 | 构建期 `pip install`（ragas 等）从 PyPI/镜像源下载停滞，30–48 分钟无进展 |
| 200643 | 构建期 pip 对 `files.pythonhosted.org` 读超时 |
| 232543 | 换清华源后 BuildKit 内仍 989.9s 读超时 |

### 8.3 本轮新增的环境修复（已固化）

1. **docker-compose.yml**：`skillevaluator` 服务加 `DOCKER_BUILDKIT: "0"`（Harbor 构建不走 BuildKit 元数据解析）。
2. **预构建判官依赖镜像** `skillevaluator-deps:3.12`：用运行时网络（`docker run`，速度正常）安装 apt 依赖 + RAGAS / openai / anthropic / boto3 等 verifier 依赖，并预建 `/workspace`、`/logs` 目录、`WORKDIR /workspace`。
3. **`.env`**：新增 `SKILLEVALUATOR_BASE_IMAGE=skillevaluator-deps:3.12`，SkillEvaluator 直接复用该基础镜像，跳过构建期 pip。
4. **calculator 的 `evals/config.yml`**：`harbor.base_image_mode: reuse`，启用共享基础镜像模式。
5. 镜像内 `skillevaluator/tier3/harbor/adapter.py` 打补丁（同步到源码树）：pip 使用清华 PyPI 镜像 + 支持 `SKILLEVALUATOR_BASE_IMAGE` 复用。
6. 既有兼容项：`SKILLEVALUATOR_FORCE_PATH_COPY=1`、opencode 模型标识 `openai/qwen3.8-flash`、`SKILLSPECTOR_MAX_LLM_CONCURRENCY=2`、`UV_INDEX_URL` 阿里云源。

> 注：`skill-evaluation-pipelines/SkillEvaluator/` 为 vendor 目录（未跟踪）；重建镜像后需重新应用上述补丁，或保留 `skillevaluator-deps:3.12` 镜像。
